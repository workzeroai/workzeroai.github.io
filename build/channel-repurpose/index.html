제 시스템에서 운영 중 · 실패 사고 포함자동화로 만드는 것

글 하나를 채널마다 다시 쓰지 않기

글을 하나 쓰면 끝이 아니죠. Threads용으로 자르고, 인스타용으로 줄이고, 링크드인용으로 고쳐 쓰고, 각각 예약까지 걸어야 합니다. 쓰는 시간보다 옮기는 시간이 더 걸리는 일이 자주 생깁니다.

이 자동화는 원문 하나를 채널별 초안으로 바꿔 예약 대기열에 넣어두는 것까지 합니다. 발행은 하지 않습니다. 이유는 아래에 적었어요.

얻는 것

  • 옮겨 적는 시간이 사라집니다

    원문을 승인하면 채널별 초안이 대기열에 들어가 있습니다. 사람이 하는 일은 읽고 고치고 발행 버튼을 누르는 것뿐이에요.

  • 채널마다 형식이 흔들리지 않습니다

    카드 몇 개로 자를지, 한 장에 몇 자를 담을지, 줄바꿈을 어디서 할지를 규칙으로 고정합니다. 사람이 그때그때 감으로 자르면 글마다 모양이 달라져요.

  • 발행 사고가 구조적으로 막힙니다

    자동으로 나가는 건 초안까지입니다. 잘못 만들어진 글이 사람 눈을 거치지 않고 계정에 올라가는 경로 자체를 두지 않아요.

지금, 그리고 바뀌면

지금

  1. 원문을 쓰고 승인합니다
  2. Threads용으로 문단을 자르고, 길이를 줄이고, 줄바꿈을 다시 넣습니다
  3. 인스타용으로 다시 줄이고 해시태그를 붙입니다
  4. 채널마다 예약 화면에 들어가 하나씩 시간을 지정합니다
  5. 어느 글이 어느 채널에 올라갔는지 따로 적어 둡니다

바뀌면

  1. 원문을 승인합니다
  2. 채널별 문법에 맞게 변환된 초안이 예약 대기열에 들어갑니다
  3. 사람은 초안을 읽고 고치고 발행 버튼을 누릅니다
  4. 무엇이 어느 채널에 몇 시에 올라갔는지 기록이 남습니다

어떻게 만드나

  • 트리거

    원문이 '승인' 상태가 되면 시작합니다. 시각 기준(매일 몇 시)으로 걸 수도 있어요.

  • 변환

    채널별 규칙으로 다시 씁니다. 글자 수 한도, 카드 분할 개수, 줄바꿈 단위, 링크 위치가 전부 규칙입니다.

  • 검증

    글자 수 초과, 빈 카드, 깨진 링크를 변환 직후에 확인합니다. 하나라도 걸리면 초안을 만들지 않고 멈춥니다.

  • 적재

    예약 대기열에 초안으로 넣습니다. 날짜·시간은 지정하되 발행 상태로 바꾸지 않습니다.

  • 기록

    어떤 원문이 어느 채널에 언제 들어갔는지 한 줄 남깁니다. 이 기록이 다음 단계의 입력이 됩니다.

원문 → Threads · 인스타그램 · 링크드인 초안

망가지면

2026년 9월 11일, 쓰던 예약 도구(Buffer)의 API가 쓰기를 막았습니다.

문제는 막혔다는 게 아니라 25일 동안 몰랐다는 것입니다. 작업은 매일 정상 종료로 찍혔고, 실제로 만들어진 초안만 0건이었어요. 로그에는 실패가 안 남고 "오늘 할 일 없음"처럼 보였습니다.

원인은 그 전부터였습니다. 감지·작성·발행을 한 번에 처리하던 구조라, 중간에 끊기면 어디까지 갔는지가 아무 데도 안 남았습니다. 2026년 8월에도 같은 이유로 6개 채널의 새 글이 통째로 누락된 적이 있어요.

  • 단계를 쪼갭니다. 감지 / 변환 / 적재를 따로 돌립니다.
  • 각 단계가 끝날 때마다 상태를 파일에 남깁니다(pending → content_ready → draft_created).
  • 실패하면 상태를 되돌리지 않습니다. 그대로 두면 다음 실행이 알아서 이어받아요.
  • "오늘 0건"과 "오늘 실패"를 구분해 알립니다. 이 둘이 같아 보이면 조용한 실패가 또 생깁니다.

안 되는 것

  • 발행까지는 자동화하지 않습니다

    요청하시면 가능합니다. 다만 권하지 않아요. 변환이 한 번 잘못되면 그대로 계정에 올라가고, 플랫폼에 따라 발행된 글은 API로 수정·삭제가 막혀 있습니다. 실제로 겪었습니다.

  • 플랫폼 API 정책에 묶입니다

    예약 도구나 플랫폼이 정책을 바꾸면 그날로 멈출 수 있습니다. 그래서 '멈춘 걸 바로 아는 것'을 같이 만듭니다.

  • 원문 품질을 올려주지는 않습니다

    변환은 형식을 맞추는 일입니다. 원문이 약하면 채널별로 약한 글이 세 개 생길 뿐이에요. 글 자체의 품질은 다음 레시피(품질 검수)가 담당합니다.

  • 채널 규칙을 먼저 정해야 합니다

    '우리 Threads는 카드 몇 개, 한 장에 몇 자'가 정해져 있지 않으면 자동화할 대상이 없습니다. 안 정해져 있으면 그걸 같이 정하는 것부터 시작합니다.

만드는 과정

  • 1주차
    채널별 규칙을 글로 고정합니다. 길이·분할·줄바꿈·링크 위치. 기존에 잘 나간 글을 샘플로 역산해요.
  • 2주차
    변환과 검증을 만들고 과거 글 10편으로 돌려봅니다. 사람이 쓴 것과 나란히 놓고 비교합니다.
  • 3주차
    예약 대기열 연동과 상태 기록을 붙입니다. 실패했을 때 어떻게 알게 되는지까지 확인하고 넘겨드립니다.
