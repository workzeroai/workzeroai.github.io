같은 스택으로 크몽에서 판매 중자동화로 만드는 것

이 자동화는 실제로 이렇게 만들어집니다

자동화를 맡길 때 가장 불안한 건 안이 안 보인다는 것입니다. 뭘 만드는지 모르는 채로 돈을 내고, 받고 나서도 어떻게 돌아가는지 모르죠.

그래서 이 페이지는 만드는 과정을 그대로 공개합니다. 어떤 도구를 왜 쓰는지, 고객님이 실제로 보게 될 화면은 무엇인지, 월 운영비는 얼마인지까지요.

개발을 모르셔도 읽으실 수 있게 썼습니다.

무슨 도구로 만드나

쓰는 도구는 다섯 개입니다. 각각이 무슨 일을 하는지 먼저 보세요.

n8n작업 순서를 실행

작업 순서를 블록으로 그려두면 그대로 실행하는 프로그램이에요. 엑셀 매크로의 인터넷 버전이라고 보시면 됩니다. '원문이 들어오면 → 글자 수를 세고 → 채널별로 바꾸고 → 예약함에 넣어라'를 그림으로 그려둡니다.

Airtable고객님이 보는 화면

엑셀처럼 생겼지만 버튼·상태·알림이 붙는 데이터베이스예요. 실제로 만지시는 화면이 여기 하나뿐입니다. 초안을 읽고, 고치고, 발행 시간을 정하는 곳이에요.

OpenAI API채널별로 바꿔 쓰기

ChatGPT를 사람이 아니라 프로그램이 대신 부르는 방식이에요. 같은 모델인데 사람이 창을 열지 않아도 자동으로 호출됩니다.

예약 발행 도구정해진 시각에 올리기

Threads·인스타그램은 공식 예약 기능이 제한적이라 전용 도구를 씁니다(Publer 등). 대기열에 넣어두면 정해진 시각에 올라가요.

Railway24시간 켜두는 서버

n8n을 계속 돌리려면 꺼지지 않는 컴퓨터가 필요해요. 고객님 노트북을 켜둘 필요가 없게 하는 장치입니다.

원문 하나가 초안이 되기까지

원문 하나가 채널별 초안이 되기까지 5단계를 지납니다.

  • 원문이 '승인'으로 바뀌면 시작

    Airtable에서 상태를 '승인'으로 바꾸는 순간 n8n이 깨어납니다. 매일 정해진 시각으로 걸 수도 있어요.

  • 채널 규칙에 맞춰 다시 쓰기

    글자 수 한도, 카드 분할 개수, 줄바꿈 위치, 링크 자리를 규칙으로 미리 정해두고 OpenAI에 그 규칙과 함께 넘깁니다. 매번 감으로 자르지 않아요.

  • 내보내기 전에 기계가 검사

    글자 수 초과, 빈 카드, 깨진 링크를 확인합니다. 하나라도 걸리면 초안을 만들지 않고 멈춥니다. 잘못된 걸 만들어 두는 것보다 안 만드는 게 낫거든요.

  • Airtable에 초안으로 쌓기

    고객님이 읽고 고칠 수 있게 올라옵니다. 이 단계에서 사람이 반드시 한 번 봅니다.

  • 승인하면 예약 대기열로

    발행 시간을 정하면 예약 도구로 넘어갑니다. 발행 후 성공·실패와 링크가 다시 Airtable에 기록돼요.

고객님이 보시는 화면

고객님이 실제로 보게 되는 화면은 Airtable 하나입니다.

  • n8n 화면은 안 보셔도 됩니다. 제가 만들고 제가 고칩니다
  • 표에서 초안을 읽고, 고칠 곳만 고치고, 발행 시간을 입력하면 끝이에요
  • 어떤 글이 어느 채널에 언제 올라갔는지 같은 표에 쌓입니다
  • 개발자용 화면이 아니라 비기술 운영자가 바로 쓸 수 있는 구조로 설계합니다

왜 이 도구인가

도구 선택에는 이유가 있습니다. 상담 때 자주 받는 질문입니다.

왜 Make가 아니라 n8n인가요?

Make로도 됩니다. 다만 조건 분기가 많아지고 API를 직접 붙여야 할 때 n8n이 유리해요. 채널마다 규칙이 다른 작업은 분기가 금방 늘어납니다. Make를 쓰시던 분이면 상담 때 말씀해 주세요.

왜 Notion이 아니라 Airtable인가요?

Notion도 가능하지만 기본은 Airtable을 권합니다. 상태 관리와 검수 흐름이 장기 운영에 더 편해요. 이미 Notion으로 돌아가는 팀이면 상담 후 가능 여부를 확인합니다.

왜 완전 자동으로 발행하지 않나요?

기술적으로는 됩니다. 권하지 않을 뿐이에요. AI 글 품질과 플랫폼 정책을 같이 보면 검수 단계를 남기는 쪽이 장기적으로 안전합니다. 발행된 글은 플랫폼에 따라 수정·삭제가 막히기도 하고요.

자동화가 어느 날 조용히 멈추면, 며칠 만에 아시겠어요?

자동화에서 제일 손해 보는 경우가 이겁니다. 매일 '정상 종료'로 찍히는데 결과물만 0건이면, 그날 올릴 게 없었던 건지 망가진 건지 구분이 안 되거든요.

  • 발행 로그를 남깁니다 — 성공·실패·발행 링크가 Airtable에 쌓입니다
  • 실패하면 알림이 갑니다(이메일 또는 협의한 채널)
  • 단계마다 상태를 남겨서 어디까지 갔는지가 보입니다
  • 납품할 때 "이게 멈춘 걸 어떻게 아는지"를 같이 보여드리고 넘깁니다

제 콘텐츠 시스템이 예약 도구 API 차단으로 25일간 조용히 실패한 적이 있습니다. 그 뒤로 로그와 알림을 기본에 넣습니다.

시작하려면 필요한 것

시작하려면 아래가 필요합니다. 없으시면 상담 때 같이 준비해요.

꼭 필요해요

  • 올릴 채널 계정 (Threads는 인스타그램·페이스북 연동 필요)
  • Airtable 계정 — 무료로 시작 가능합니다
  • OpenAI API Key — 글을 바꿔 쓰는 데 씁니다
  • 예약 발행 도구 계정
  • n8n 실행 환경 (Railway 또는 n8n Cloud)

있으면 좋아요

  • 기존에 올려서 반응이 좋았던 글 3~5개 — 채널 규칙을 여기서 역산합니다
  • 브랜드 톤과 쓰면 안 되는 표현 정리

매달 나가는 돈

제작비와 별개로 매달 나가는 돈이 있습니다. 고객님 계정에서 직접 나가고, 저를 거치지 않아요.

Railway 또는 n8n Cloud월 7,000~17,000원
OpenAI API월 1,000~5,000원
Airtable무료~유료 (데이터량에 따라)
예약 발행 도구플랜별 상이
하루 3건 발행 기준 월 2~5만 원 수준입니다. 발행량이 늘면 같이 늘어나요.

안 되는 것

  • 계정 제재가 없다고 보장하지 않습니다

    플랫폼 정책이 바뀌거나 계정 설정에 따라 생길 수 있어요. 발생하면 가능한 범위에서 확인해 드리지만, 막아드린다고 말씀드릴 수는 없습니다.

  • 다계정 동시 운영은 별도입니다

    계정이 여러 개면 구조가 달라집니다. 상담에서 따로 봐야 해요.

  • 원문 품질을 올려주지는 않습니다

    변환은 형식을 맞추는 일이에요. 원문이 약하면 약한 글이 채널 수만큼 생깁니다.

  • 타인 콘텐츠를 긁어오는 구조는 만들지 않습니다

    요청하셔도 안 합니다.

만드는 순서

  • 1단계
    상담에서 범위를 정합니다. 채널 몇 개, 하루 몇 건, 소재는 직접 넣는지.
  • 2단계
    계정·API 준비 상태를 확인합니다. 여기가 늦어지면 일정도 같이 밀려요.
  • 3단계
    Airtable 구조를 설계합니다 — 고객님이 보실 화면입니다.
  • 4단계
    n8n 워크플로우를 만들고 채널 규칙을 넣습니다.
  • 5단계
    테스트 콘텐츠로 실제 발행까지 돌려봅니다.
  • 6단계
    화면공유로 사용법을 안내합니다. 완료 후 7일 이내 기본 오류는 무상으로 확인해요.
