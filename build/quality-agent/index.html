제 시스템에서 운영 중 · 44.7만자를 이 방식으로 검수에이전트로 만드는 것

올리기 전에 매번 하던 검수를 넘기기

콘텐츠를 올리기 전에 보는 것들이 있죠. 톤이 우리 같은가, 쓰면 안 되는 표현이 들어갔나, 필수 문구는 빠지지 않았나, 숫자는 맞나.

문제는 이게 양에 비례해서 늘어난다는 겁니다. 하루 한 편이면 괜찮은데 다섯 편이 되면 검수가 병목이 되고, 그러다 보면 결국 안 보고 올리게 돼요.

얻는 것

  • 검수가 발행량을 막지 않습니다

    사람이 다 읽어야만 나갈 수 있는 구조에서, 사람이 '고칠 곳만' 보면 되는 구조로 바뀝니다. 제 경우 132편 44.7만자(평균 3,383자)를 이 방식으로 처리했어요. 전부 손으로 읽었다면 못 했을 분량입니다.

  • 기준이 사람 머릿속에서 문서로 나옵니다

    에이전트에게 검수를 시키려면 기준을 글로 적어야 합니다. 이 과정에서 '왜 이게 어색한지'가 규칙으로 남아요. 담당자가 바뀌어도 기준이 남는 게 실제 이득입니다.

  • 놓치는 패턴이 줄어듭니다

    사람은 같은 글을 세 번째 읽으면 같은 실수를 지나칩니다. 한 곳에서 문제를 찾으면 같은 패턴이 다른 곳에도 있는지 전체를 다시 훑는 식으로 돌립니다.

지금, 그리고 바뀌면

지금

  1. 초안이 올라옵니다
  2. 담당자가 처음부터 끝까지 읽습니다
  3. 톤·금지어·필수 문구·숫자를 눈으로 확인합니다
  4. 고칠 곳을 코멘트로 남기고 다시 돌려보냅니다
  5. 바쁜 날은 훑고 넘깁니다

바뀌면

  1. 초안이 올라옵니다
  2. 항목별 점수표와 '여기를 이렇게 고치면 됩니다'가 먼저 도착합니다
  3. 담당자는 제안을 보고 받을지 말지 판정합니다
  4. 기준을 바꾸고 싶으면 규칙 문서를 고칩니다. 다음 글부터 바로 적용돼요

어떻게 만드나

  • 기준 문서화

    브랜드 톤, 금지 표현, 필수 문구, 숫자 표기 규칙을 파일로 만듭니다. 이게 에이전트의 채점 기준이자, 사람이 읽는 가이드가 됩니다.

  • 문체 검사

    번역투, 어색한 사역 표현, 동사 없이 뚝 끊기는 명사형 종결, 3회 이상 반복되는 수사를 찾습니다. 제 경우 공개된 한국어 문체 룰북(im-not-ai)을 기준으로 씁니다.

  • 사실 검사

    숫자와 인용문을 원본과 한 글자씩 대조합니다. 고유명사·제품명 오타는 특히 발음이 비슷한 것끼리 바뀌기 쉬워서 원문과 다시 맞춰봅니다.

  • 전체 재검색

    한 군데를 고치면 같은 패턴이 다른 곳에도 있는지 문서 전체를 다시 훑습니다. 통과할 때까지 반복합니다.

  • 보고

    점수표 + 고칠 위치 + 수정안을 냅니다. 고쳐서 덮어쓰지 않고 제안만 합니다.

브랜드 가이드 · 콘텐츠 초안 → 점수표 · 수정안

망가지면

검수 에이전트에서 제일 위험한 실패는 멈추는 게 아닙니다. 멋대로 고치는 것이에요.

문체를 다듬으라고 시키면 숫자나 고유명사까지 '자연스럽게' 바꿔버리는 일이 생깁니다. 금액이 바뀌거나 제품명이 비슷한 다른 이름으로 교체되는 식이죠. 글은 더 매끄러워지는데 내용이 틀려집니다. 사람이 읽어도 매끄러우니까 안 걸립니다.

실제로 저는 글 127편의 문체를 한꺼번에 바꾼 적이 있는데, 그때 바꾼 것이 톤뿐인지를 따로 검사해야 했습니다.

  • 의미·수치·고유명사는 건드리지 않는다를 기준 문서 1번에 박아둡니다.
  • 검수는 덮어쓰지 않고 제안만 합니다. 반영 여부는 사람이 누릅니다.
  • 일괄 적용을 했으면 전수 검사를 합니다. 저는 127편 전부에 대해 바뀐 게 문체뿐인지 기계로 확인했어요.
  • 통과 기준을 숫자로 둡니다. '자연스럽게'는 검사할 수 없지만 '문어체 종결 비율'은 셀 수 있습니다.

안 되는 것

  • 기준이 없으면 못 만듭니다

    '우리 톤'이 사람 머릿속에만 있으면 채점할 수가 없어요. 잘 쓴 글 10편, 못 쓴 글 5편을 놓고 왜 그런지 말로 뽑아내는 것부터 시작합니다. 보통 여기가 제일 오래 걸립니다.

  • 취향은 자동화되지 않습니다

    맞춤법·금지어·필수 문구·숫자는 기계가 잡습니다. '이 표현이 우리답나'는 끝까지 사람 판정이에요. 그래서 점수표를 주고 사람이 받을지 정하는 구조로 만듭니다.

  • 처음 몇 주는 사람이 더 바쁩니다

    에이전트가 잘못 짚은 걸 교정해 줘야 기준이 정확해집니다. 보통 2~3주는 사람이 더 손이 갑니다. 이걸 안 알려드리면 '생각보다 별로네'가 됩니다.

  • 남의 글을 검수할 때는 더 조심합니다

    외부 자료를 요약·인용하는 콘텐츠라면 사실 오류가 그대로 공개됩니다. 이때는 문체보다 원문 대조를 먼저 겁니다.

만드는 과정

  • 1주차
    잘 쓴 글과 아닌 글을 놓고 기준을 뽑아냅니다. 금지 표현·필수 문구·숫자 표기까지 문서 한 장으로 만듭니다.
  • 2주차
    채점과 수정안 생성을 만들고 과거 글로 돌려봅니다. 담당자가 '이건 맞고 이건 틀렸다'를 교정해 기준을 조입니다.
  • 3주차
    통과 기준을 숫자로 고정하고, 일괄 적용했을 때 쓸 전수 검사까지 붙여 넘겨드립니다.
