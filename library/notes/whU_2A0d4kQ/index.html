이제 영상 편집하는데 시간낭비하지 마세요

출처 · 투쏠ㅣAI 에이전트이 글은 아래 영상 내용을 한국어로 요약·정리한 것입니다. 원문의 주장과 수치는 영상 제작자의 것입니다.
원본 영상 보기 →
핵심
  • 편집 툴 자체의 AI 자막 기능을 믿지 마세요
  • 파일 경로 하나가 에이전트 자동화 여부를 가릅니다
  • 가이드와 수치 기준이 없으면 AI는 대충 만들어요

한 줄 요약

캡컷(CapCut)으로 촬영과 1차 자막까지는 수동으로 하고, 그 이후 인트로 편집(컷 전환, 애니메이션, 스타일)은 캡컷 프로젝트의 드래프트 파일 경로를 직접 지정한 AI 에이전트에게 맡기는 반자동 편집 워크플로우예요. 처음부터 끝까지 실제 화면으로 보여 줍니다.

전체 내용 정리

100% 자동화가 아니라 '하이브리드'로 가는 이유

발표자는 캡컷을 쓰면서 GPT나 클로드와 함께 영상을 편집하는데, 100% 자동화는 아니라고 못 박아요.

촬영은 미리 쭉 녹화해 두고, 컷 편집은 수동으로 직접 합니다. AI가 컷을 잡아 줄 수는 있지만 본인이 말이 빠르고 발음이 정확하지 않아서 AI가 부정확하게 잡는 경우가 많거든요.

그래서 촬영 후 컴퓨터로 옮겨 완전한 폴더를 만드는 것까지는 사람이 하고, 인트로처럼 디자인과 애니메이션이 들어가는 구간부터 AI 에이전트에게 넘깁니다.

프로젝트 세팅

캡컷을 켜고 새 프로젝트를 만든 뒤, 촬영해 둔 폴더 전체를 그대로 업로드해요. 이후 실제로 편집이 필요한 구간까지 타임라인에 빼놓으면 1차 준비가 끝납니다. 프로젝트 이름은 날짜 기준으로 바꿔 두고요("9월 18일 인트로 촬영" 같은 식으로요).

발표자는 원래 "아스트라"를 쓰고 싶었는데 사용량이 1%밖에 안 남아서, 이번 영상에서는 클로드 페이블 5.1로 작업했다고 밝혀요.

자막은 캡컷 말고 별도 사이트에서

캡컷 자체 AI 자막 생성 기능은 품질이 매우 떨어진다고 지적합니다. "쓰레기처럼 나온다"고요.

많은 사람이 쓰는 "부루" 같은 툴 대신, 발표자는 터보스크라이브라는 사이트를 씁니다. 하루 3건까지 무료이고 한국어 전사 품질이 특히 좋다고 해요.

대시보드에서 파일을 업로드하고 모델을 "고래" 모델(가장 정확하다고 언급합니다)로 선택해 전사하면, 캡컷 자체 자막보다 훨씬 깔끔한 스크립트가 나옵니다. 틀린 단어가 있으면 전사 편집 화면에서 해당 문장을 클릭해 바로 수정할 수 있고, 완료되면 SRT 파일을 다운로드해요.

캡컷으로 돌아와 자막 스타일 입히기

다운로드한 SRT 파일을 캡컷의 "캡션 추가" 기능으로 불러오면 문장 단위로 깔끔하게 배치됩니다(무료 버전이라 워터마크성 표시가 한 줄 붙는 건 감안해야 해요).

텍스트 스타일은 프리텐다드 엑스트라 볼드체를 기본으로 쓰고, 스타일 목록 중 네 번째 스타일에서 불투명도 값을 조정해 깔끔한 자막 스타일을 완성합니다.

핵심은 드래프트 파일 경로예요

이 영상에서 가장 핵심적인 단계입니다.

캡컷을 완전히 종료한 뒤, 사용자 PC의 캡컷 폴더 안에서 "유저 데이터 > 프로젝트" 경로를 따라가면 "LV 에디터 드래프트"라는 폴더가 있어요.

이 폴더의 경로를 알고 있으면, 클로드나 GPT 같은 AI가 그 경로에 있는 드래프트(JSON) 파일을 직접 열어 읽고 써서 실제 캡컷 편집 내용을 바꿀 수 있게 됩니다.

경로를 직접 찾기 어렵다면 클로드 코워크에서 캡컷 폴더를 프로젝트 폴더로 추가한 뒤 "LV 에디터 폴더를 찾아 주고 경로를 알려 줘"라고 요청하면 빠르게 얻을 수 있다고 안내해요.

'캡컷 에디 에이전트'에게 인트로 편집 맡기기

발표자는 자신만의 프레임워크로 구성한 "캡컷 에디 에이전트"를 미리 만들어 뒀고, 이를 ABC 클럽에 올려 다운로드할 수 있게 할 예정이라고 합니다.

클로드에서 해당 에이전트 폴더를 지정하고, 앞서 찾은 드래프트 경로를 복사해 붙여넣은 뒤 먼저 "이 인트로를 인식할 수 있는지 확인해 줘"라고 요청해요. 에이전트는 드래프트 폴더를 스스로 열어 구조와 타임라인을 확인하고, 드래프트 JSON 파일을 직접 읽고 쓸 수 있어 자막 수정·트랙 추가·세그먼트 배치가 파일 처리 단위로 가능하다고 응답합니다.

이어서 구체적인 편집 지시를 줘요.

  • 브랜드 가이드라인 색상은 체리필터 색으로 지정
  • 문장(어절) 단위마다 화면 전환이 최소 2~3번씩 일어나야 시청자 이탈을 막을 수 있다는 기준
  • 클로드 페이블 5.1 내부의 기본 스타일 지침을 크게 따를 필요는 없으니 먼저 러프하게 뽑아 달라고 요청

인트로 폴더와 SRT 파일을 업로드한 뒤, 계획은 페이블 5.1로 세우되 실제 구현은 클로드 오퍼스(Opus) 4.5 모델로 진행하도록 지정해서 요청합니다. 계획이 나오면 검토 후 모델을 오퍼스로 바꾸고 추론 강도를 "높음"으로 설정해 실행을 지시해요.

에이전트는 작업을 마친 뒤 캡컷을 종료하고 드래프트에 결과를 주입하며, 드래프트 JSON을 다시 읽어 트랙 순서와 타이밍을 검증했다고 보고합니다.

결과를 보며 반복 피드백으로 다듬기

캡컷을 다시 열어 보니 기존 영상 위에 새 인트로가 얹혀 나왔어요.

첫 결과는 컷이 너무 많아서 "너무 난잡하다"는 문제가 있었습니다. 발표자는 컷수를 절반 이하로 줄이고 "한 어절 동안 이어 가다 세 어절마다 한 번 전환" 같은 패턴으로, 전체 컷수를 15컷 이하로 줄여 달라고 다시 요청해요. 재작업 결과는 훨씬 깔끔해졌습니다.

비교 실험도 보여 줍니다. 자신이 만든 에이전트 가이드 없이 그냥 클로드 페이블 5.1에만 맡겨 봤더니, 컷 구분이나 편집 없이 원본 영상을 거의 그대로 이어붙인 수준의 결과물이 나왔어요.

이걸로 강조하는 건 이겁니다. 리모션(Remotion) 같은 렌더링 엔진은 그냥 맡기기만 해서는 좋은 결과가 안 나오고, 구체적인 가이드와 예시를 함께 줘야 합니다. 참고로 캡컷 에디터 작업에는 리모션과 하이퍼프레임 두 가지를 쓸 수 있는데, 발표자는 주로 리모션을 활용해요.

마지막으로 화면 중앙에 보이는 검은색 띠 형태의 요소가 마음에 들지 않아, 이를 빼고 다른 애니메이션으로 대체해 달라고 말로 요청해 다시 렌더링을 받습니다. 수정 결과는 훨씬 깔끔해졌어요. 이후에도 마음에 안 드는 부분을 캡처해서 지정하거나 말로 설명하는 방식으로 계속 다듬어 나갈 수 있다고 설명합니다.

왜 하이브리드를 선호할까요

발표자는 영상 전공자가 아닌 사람들에게는 완전 자동화보다 직접 고칠 부분은 고치고 AI에게 맡길 부분은 맡기는 하이브리드가 더 현실적이라고 말해요.

그리고 하나 더. 편집 요청을 타이핑 대신 말로 설명해 AI에게 전달하는 방식이 훨씬 빠르고, 구조적으로 정리된 형태로 전달된다는 점도 장점으로 꼽습니다. 이 말로 하는 전달 과정이 없었다면 촬영과 편집 시간이 훨씬 더 길어졌을 거라고 해요.

핵심 인사이트

  • 편집 툴 자체의 AI 자막 기능을 믿지 마세요: 캡컷 내장 자막 생성은 품질이 낮아서, 별도 전사 전문 서비스로 SRT를 뽑아 다시 넣는 우회 경로가 실제로는 훨씬 결과물이 깔끔합니다.
  • 파일 경로 하나가 에이전트 자동화 여부를 가릅니다: 캡컷의 "LV 에디터 드래프트" 폴더 경로만 AI에게 넘겨주면, AI가 드래프트 JSON을 직접 읽고 써서 실제 프로젝트를 조작할 수 있어요. 이런 내부 파일 경로를 찾아 넘기는 게 편집 도구를 AI 에이전트화하는 핵심 열쇠입니다.
  • 가이드와 수치 기준이 없으면 AI는 대충 만들어요: 브랜드 컬러, 전환 빈도, 컷수 상한 같은 구체적인 기준을 주지 않고 그냥 "만들어 줘"라고 하면 컷 구분조차 안 된 부실한 결과가 나옵니다. 반복적인 피드백으로 결과를 다듬어 가는 과정이 필수예요.

오늘 당장 해볼 것

  1. 터보스크라이브에서 영상 파일을 업로드하고 "고래" 모델로 전사한 뒤 SRT를 다운로드해 보세요(하루 3건 무료). 쓰던 편집 툴 자체 자막 기능과 비교해 보면 차이가 바로 보입니다.
  2. 쓰는 편집 툴의 사용자 데이터 폴더에서 프로젝트 드래프트 파일이 저장되는 경로를 찾아 메모해 두세요. 못 찾으면 클로드 코워크에 편집 툴 폴더를 추가하고 "드래프트 저장 폴더를 찾아서 경로를 알려 줘"라고 하면 됩니다.
  3. AI에게 영상 편집이나 디자인을 요청할 때 "브랜드 컬러는 이 색으로", "전환은 몇 번마다", "컷수는 몇 개 이하로" 같은 구체적 수치 기준을 먼저 주세요. 결과를 본 뒤 마음에 안 드는 요소를 짚어 말로 다시 요청하는 반복 방식이 제일 빠릅니다.
