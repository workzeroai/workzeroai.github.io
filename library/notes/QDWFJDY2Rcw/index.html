내 하루 업무 90%를 처리하는 클로드 세팅 공개

핵심
  • 챗봇과 에이전트 도구의 차이가 생산성 차이를 만들어요
  • CLAUDE.md와 스킬이 진짜 자동화의 복리 효과를 만들어요
  • 모든 업무는 결국 파일-도구-웹-스케줄, 4가지 조합으로 환원돼요

한 줄 요약

"코딩 도구"라는 이름 때문에 대부분이 지나치는 Claude Code, 혹시 그러셨나요. 60개 이상 업체에 AI 자동화를 붙여온 저자가 비개발자도 코드 한 줄 없이 쓸 수 있는 실전 세팅법으로 풀어낸 영상이에요. 영수증 정리·대시보드 제작·회의록 자동화·미수금 추심까지 돌립니다.

전체 내용 정리

챗봇과 다른 점 — Claude Code는 조언이 아니라 실제로 일을 처리해요

ChatGPT나 일반 Claude 챗봇은 브레인스토밍이나 질문 답변에는 훌륭하지만, 결국 "조언"만 주잖아요. 파일을 분석해달라면 매번 업로드해야 하고, 정리 방법을 물으면 방법만 알려줄 뿐 실제로 정리해주지는 않죠.

Claude Code는 이 구조를 완전히 뒤집습니다. 컴퓨터의 특정 폴더를 지정해주고 할 일을 말하면, 그 폴더 안의 파일을 직접 읽고, 새 파일을 만들고, 저장하고, 다음에도 같은 방식으로 일하도록 기억까지 남겨요.

저자는 이 차이를 이렇게 설명합니다. "동료에게 조언 구하기"와 "유능한 비서에게 프로젝트를 맡기고 끝날 때 확인하는 것"의 차이라고요.

원래 2024년 개발자용 터미널 도구로 출시됐는데요. Anthropic 자체 조사에 따르면 실제 사용량의 3분의 2는 코딩이 아닌 일반 업무였습니다. 여행 계획, 파일 정리, 문서 작성, 리서치 같은 것들이죠.

실제 사례도 있어요. Anthropic 법무팀은 전화 시스템 프로토타입을 만들었고, 마케팅팀은 광고 변형 수백 개를 직접 생성했으며, PwC는 10주 걸리던 프로세스를 10일로 줄였다고 밝혔습니다.

설정은 딱 3단계 — 모델 고르고, 전용 폴더 만들고, 권한 모드 정하기

Claude Code는 데스크톱 앱, 웹 브라우저(claude.ai), 터미널, IDE(Cursor, VS Code, WindSurf 등) 어디서든 쓸 수 있고, 어떤 걸 쓰든 상관없어요.

설정은 세 가지뿐입니다.

첫째, 모델 선택. Fable 5(최상위), Opus 5, 일상 업무엔 Sonnet 5, 단순 반복 작업엔 Haiku 4.5를 쓰세요. 추론이 복잡하면 effort를 medium에서 high로 올리시면 됩니다.

둘째, 전용 폴더 만들기. 컴퓨터 전체가 아니라 업무용으로 분리한 폴더 하나를 Claude Code에 열어주세요.

셋째, 권한 모드 결정. 처음엔 모든 작업을 하나하나 승인하는 매뉴얼 모드로 시작해서, 익숙해지면 자동 승인되는 오토 모드로 넘어가시면 돼요.

안전 수칙으로 저자는 은행 정보나 규제 대상 고객 데이터가 든 폴더는 애초에 보여주지 말라고 강조합니다. 가장 안전한 방법은 애초에 민감 정보를 보이지 않게 하는 거예요.

데모 1~2 — 영수증 폴더를 엑셀 장부로, 판매 데이터를 대시보드로

첫 데모는 뒤죽박죽인 영수증·인보이스 파일 42개(사진·PDF 혼합)가 든 폴더를 통째로 넘기는 거였어요.

프롬프트는 이랬습니다. 벤더·날짜·금액·용도를 뽑아 날짜/벤더/카테고리/금액 열을 가진 엑셀 장부를 만들고, 카테고리별·월별 합계 시트를 추가하며, 중복 의심 건과 세금 공제 가능 건을 표시하고, 읽을 수 없는 파일은 추측하지 말고 "검토 필요" 시트에 따로 모으라고요.

약 2분 만에 39건이 장부에 정리되고 3건이 읽을 수 없어 별도 표시됐어요. 수익 항목처럼 범위 밖의 데이터는 알아서 제외하고 확인을 요청했습니다.

두 번째 데모는 매장 판매 데이터 CSV(약 1,300행)를 넘기고, 월별 매출·상위 5개 상품·평균 주문 금액·재구매 고객 매출 비중을 다크 테마·모바일 대응 웹 대시보드로 만들어달라는 거였어요. Claude가 Playwright로 직접 브라우저를 조작해 모바일 화면까지 확인하며 만들었고, 로컬 HTML 파일과 열람 링크를 함께 제공했습니다.

두 데모 모두 핵심은 "같은 프롬프트 구조, 다른 폴더"일 뿐이라는 점이에요. 업종과 무관하게 계약서·이력서·환자 접수서·보증 청구서 등 어디에나 적용 가능하죠.

데모 3~4 — 미팅 노트를 회의록+슬라이드로, 밀린 인보이스를 회수 이메일 초안으로

세 번째 데모부터는 파일이 아니라 "커넥터"로 이미 쓰는 도구에 로그인해 작업해요. 이메일, 드라이브, CRM, 노트테이커, 회계 소프트웨어 같은 것들이죠.

Fireflies에서 최근 미팅 녹취록을 가져와, 논의 내용·미해결 사항·담당자와 기한이 명시된 다음 단계를 담은 한 페이지 요약과, 그 다음 단계를 보여주는 슬라이드 덱을 만들라는 프롬프트를 실행했습니다.

저장 폴더가 없다는 확인 질문에 답하며 약 6분 만에 마크다운 요약과 HTML 슬라이드가 생성됐어요. 민감한 발언은 그대로 인용하고 없는 내용은 지어내지 말라는 규칙도 지켜졌습니다.

네 번째 데모는 밀린 인보이스 CSV를 넘기고, 미수금 총액과 각 인보이스가 어느 단계(tier)에 해당하는지 요약 파일로 만들되, 다시 실행할 때는 지난번 이후 새로 발생한 건만 처리하도록 지시했어요.

결과로 Gmail에 초안 7건이 자동으로 작성됐습니다. 아무것도 실제로 발송되지 않고 전부 승인 대기 상태로 남았어요.

저자는 이 구조를 "사람이 기억해야만 놓치지 않는" 모든 업무에 그대로 옮길 수 있다고 강조합니다. 견적 후 5일간 무응답, 6개월 이상 재예약 없는 환자, 60일 후 갱신 예정 계약 같은 것들이요.

진짜 핵심은 여섯 가지 세팅 — 메모리 파일과 스킬

네 개의 데모는 누구나 보여줄 수 있어요. 하지만 업무 전체를 실제로 맡기려면 한 번만 설정해두면 되는 여섯 가지가 필요하다고 저자는 말합니다.

첫 번째는 메모리, 즉 CLAUDE.md 파일이에요. 이 텍스트 파일에 사업 정체성, 고객, 가격, 규칙, 말투 등을 한 번 적어두면 Claude가 매 대화 시작마다 자동으로 참고하므로, 매번 맥락을 재설명할 필요가 없습니다.

저자는 이 파일조차 직접 쓰지 않았어요. Claude에게 "이 정보를 보고 CLAUDE.md를 만들어줘"라고 시켜 생성했죠. 전체 사업에 적용되는 큰 파일 하나와 특정 프로젝트·고객에만 적용되는 작은 파일을 함께 둘 수 있고, /init 명령으로 폴더를 스캔해 초안을 자동 생성할 수도 있습니다.

두 번째는 스킬(skill)이에요. 한 번 진행한 작업을 "이걸 스킬로 만들어줘"라는 한 문장으로 저장하면, 그 후로는 매번 같은 방식으로 같은 결과를 냅니다.

저자는 직전 회의록 작업을 "meeting report" 스킬로 전환하는 과정을 시연했어요. 이후엔 명시적으로 호출하지 않아도 Claude가 알아서 해당 작업에 맞는 스킬을 찾아 적용합니다. 두 번 이상 반복하는 업무는 전부 스킬로 만드세요. 이게 저자의 핵심 조언이에요.

팀으로 굴리기 — 서브에이전트, 스케줄링, 안전장치 세 가지

세 번째는 앞서 다룬 커넥터(이미 쓰는 도구에 로그인)입니다.

네 번째는 서브에이전트예요. 특정 업무 하나에 특화된 워커를 여러 개 만들어 병렬로 돌리는 건데요. 저자는 북키퍼·클라이언트 작가·경쟁사 조사·인보이스 추심·매장 분석 등 개별 에이전트를 예시로 보여줬습니다.

각 에이전트는 독립된 기억을 가지므로 서로 간섭하지 않고 동시에 작업할 수 있어요. 원래 1시간 걸릴 일이 몇 분 만에 끝나죠. 다만 처음부터 20개를 만들지 말고, 실제로 별도 레인이 필요한 업무가 생길 때마다 하나씩 추가하라는 것이 Anthropic 자체 가이드라인입니다.

다섯 번째는 스케줄링이에요. /schedule 명령으로 스킬을 매주 월요일 오전 9시처럼 정해진 시간에 자동 실행되게 만들 수 있어요. 로컬에서 돌리면 컴퓨터가 켜져 있어야 하며, 클라우드로 돌리면 별도 API 비용이 듭니다.

여섯 번째는 안전장치입니다. 플래닝 모드(작업 전 계획을 먼저 보여주고 승인받기), 권한 모드(오토/매뉴얼), undo(되돌리기) 세 가지를 결합해 통제해요.

저자는 분명히 짚습니다. 이것이 사업을 통째로 로봇에 맡기고 손을 떼라는 뜻이 아니라, 돈이 나가거나 고객에게 나가는 일은 여전히 사람이 최종 승인해야 한다는 거예요.

핵심 인사이트

  • 챗봇과 에이전트 도구의 차이가 생산성 차이를 만들어요: "조언"만 주는 AI와 "결과물"을 직접 만들어 저장하는 AI는 완전히 다른 카테고리입니다. 이름 때문에 개발자 도구로 오해받아 못 써본 사람이 절대다수라는 게 저자의 핵심 주장이며, 이 인식 격차 자체가 지금 시장의 기회죠.
  • CLAUDE.md와 스킬이 진짜 자동화의 복리 효과를 만들어요: 프롬프트를 매번 새로 쓰는 게 아니라 "한 번 가르치면 영원히 같은 방식으로 수행"하는 구조를 만드는 것이 핵심입니다. 신입 직원에게 SOP를 물려주는 것과 동일한 논리이며, 쌓일수록 자산이 돼요.
  • 모든 업무는 결국 파일-도구-웹-스케줄, 4가지 조합으로 환원돼요: 업종과 무관하게 "정보를 한 곳에서 가져와 뭔가를 하고 다른 곳에 넣는다"는 동일한 패턴이 반복된다는 인식이 있으면, 하나의 데모를 보고도 자기 업무에 바로 대입할 수 있습니다.

오늘 당장 해볼 것

  1. Claude(claude.ai 웹 또는 데스크톱 앱)에서 컴퓨터에 업무용 전용 폴더를 하나 만들고(예: Downloads/Business), 그 폴더를 Claude Code 프로젝트로 열어 연결해보세요.
  2. 그 폴더 안에 사업 개요·고객·가격·말투 규칙을 적은 CLAUDE.md 파일을 만들거나, /init 명령으로 Claude에게 초안을 자동 생성시키세요.
  3. 영수증·인보이스·판매 데이터처럼 반복적으로 쌓이는 파일 폴더 하나를 골라 첫 자동화를 실행해보세요. "각 파일을 읽고 벤더/날짜/금액/카테고리를 뽑아 엑셀 장부로 만들고, 읽을 수 없는 건 추측하지 말고 별도 시트에 모아달라" 같은 형태로요.
