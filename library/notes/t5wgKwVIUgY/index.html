2027년이 오기전 클로드 코드의 80%를 마스터 하세요 [2시간 풀코스]

출처 · 투쏠ㅣAI 에이전트이 글은 아래 영상 내용을 한국어로 요약·정리한 것입니다. 원문의 주장과 수치는 영상 제작자의 것입니다.
원본 영상 보기 →
핵심
  • CLAUDE.md는 권고, 훅은 강제
  • 컨텍스트는 비선형으로 불어나요
  • 스킬과 서브에이전트는 쓰임새가 달라요

한 줄 요약

클로드 코드(Claude Code)를 설치하는 순간부터 CLAUDE.md, 슬래시 명령어, MCP, 스킬, 서브에이전트, 훅까지 투두 앱 하나를 계속 고쳐 가며 한 흐름으로 따라 해 보는 2시간짜리 실습 강의예요. 투쏠은 클로드 코드를 "내 일을 대신할 에이전트를 만드는 도구"로 정의하고 이 흐름만 익히면 80%는 쓸 수 있다고 봅니다.

전체 내용 정리

챗·코워크·코드는 뭐가 다르고, 클로드 코드는 어떻게 켜나요?

투쏠은 GPT 아스트라와 클로드 페이블 5.1이 나온 시점을 두고 "AGI가 시작됐다"는 말이 많이 나온다고 전하면서 이제는 일을 에이전트에게 맡겨야 할 때라고 강의를 엽니다. 먼저 클로드의 세 제품부터 정리하는데요. 셋 다 같은 클로드지만 일하는 환경과 제어 수준이 달라요. 챗(Chat)은 묻고 답하는 용도로 요약·글쓰기·커넥터 검색은 하지만 내 폴더를 직접 만지지 않아요. 코워크(Cowork)는 지정한 폴더의 파일을 읽고 고치고 만들며 반복 작업 예약도 됩니다.

코드(Code)는 내 컴퓨터에서 파일 수정·터미널 명령 실행까지 하는 에이전트를 만드는 도구라 제어 수준이 가장 높고 그만큼 확인할 것도 많습니다. 투쏠은 이를 동심원으로 설명해요. 챗이 하는 일은 코워크와 코드가 다 할 수 있어요. 코워크가 하는 일도 코드는 하지만 코드가 하는 일은 나머지 둘이 못 한다는 거죠.

설치는 공식 문서에 나온 운영체제별 명령어(맥·윈도우)를 터미널에 붙여 넣고 엔터만 누르면 끝나요. 강의에서는 구글의 코드 편집기 안티그래비티(Antigravity)를 열고 오른쪽 위 터미널 메뉴에서 새 터미널을 띄운 뒤 claude를 입력해 실행합니다. 쓰는 방법은 앱, IDE 안 터미널, 확장 플러그인 세 가지가 있는데, 가장 원초적인 터미널부터 익히면 나머지는 훨씬 쉬워진다는 이유로 터미널로 진행해요. 터미널에서는 Shift+Enter가 줄바꿈이 아니라 전송이 돼 버리니, 줄을 바꾸려면 역슬래시(\)를 치고 엔터를 누르면 됩니다.

CLAUDE.md는 내 프롬프트보다 먼저 읽히는 사전 지시서예요

CLAUDE.md는 세션이 시작될 때 자동으로 읽히는 마크다운 파일이에요. 마크다운(#·굵게·대시 같은 기호로 중요도를 표시하는 문서 형식)을 쓰는 이유는, AI에게는 글씨 크기나 형광펜으로 중요한 부분을 알려 줄 수 없어서입니다. 읽히는 순서는 클로드 자체 시스템 프롬프트 → CLAUDE.md → 내 채팅이고 파일 이름은 대문자 그대로 정확히 CLAUDE.md여야 해요. "주석 달아라", "새 파일 만들기 전에 물어봐라"처럼 매번 하던 말을 적어 두면 다시 말하지 않아도 됩니다.

투쏠은 비행기 비유를 듭니다. 단거리에서는 1도 차이가 무관하지만 대서양을 건널 때는 수백 km 오차가 나듯, 짧은 대화에서는 CLAUDE.md 영향이 작아도 긴 바이브 코딩 작업에서는 초반 지침이 결과를 결정한다는 거예요. CLAUDE.md가 없으면 클로드는 목표까지 가긴 가도 경로가 제각각이에요. 반면 CLAUDE.md가 있으면 경로 범위가 좁아져 원하는 방향으로 안정적으로 갑니다. 다만 CLAUDE.md는 지침 컨텍스트일 뿐 강제 설정이 아니라서 모호하거나 충돌하는 지시는 지켜진다는 보장이 없어요. 꼭 막아야 하는 건 뒤에서 다룰 권한 설정과 훅으로 처리해야 합니다.

실습은 투두 앱이에요. 간단한 투두 앱을 HTML로 만들어 크롬에 띄워 달라고 한 뒤, 캡처를 붙여 "다크 모드 말고 흰 배경, 체크박스 세 개, 버튼은 빨간색"으로 고칩니다. 이어서 /init을 실행하면 클로드가 CLAUDE.md가 있는지 확인하고 프로젝트용으로 새로 만들어 줘요. 오른쪽 위에 오늘 날짜를 넣는 수정까지 한 뒤 "CLAUDE.md에 업데이트"를 시키고 만든 파일과 대화 기억을 모두 지운 채 새 세션에서 "투두 앱 만들어서 보여 줘"라고만 했더니 흰 배경·빨간 버튼·체크박스·날짜가 그대로 나왔습니다.

작성 원칙도 짚어요. 클로드는 CLAUDE.md를 다 읽고 100% 따르지 않으니 짧게, 불릿과 짧은 헤딩으로 쓰는 게 좋아요. 정보 밀도 높은 문장은 바로 추가하고 주기적으로 검토해 불필요한 줄을 지워야 해요. 거대한 API 문서를 통째로 붙여 넣는 건 금지고 투쏠은 100~110줄 안에서 조절하길 권합니다. 한 번에 완성되지 않으니 고치고 업데이트하는 과정을 반복해야 한다는 점도 강조해요.

마지막으로 AGENTS.md 개념이 나옵니다. CLAUDE.md는 클로드만 읽고 안티그래비티의 제미나이는 GEMINI.md, 커서는 커서용 파일을 따로 읽다 보니 같은 내용을 여러 번 복사하게 되는데요. AGENTS.md는 코덱스·커서·제미나이 같은 여러 AI 코딩 도구가 함께 읽도록 만든 공개 규격이에요. 투쏠은 클로드 코드만 쓸 게 아니라면 파일 이름을 AGENTS.md로 바꿔 못 박아 두길 추천합니다.

슬래시 명령어로 설정을 바꾸고, 컨텍스트는 /compact와 /clear로 관리해요

/를 누르면 수백 개의 명령어가 뜨고 /help로 목록을 볼 수 있어요. 기본 내장 명령어 외에 나만의 명령어도 만들 수 있습니다. /config에서 언어를 한국어로 바꾸면 영어로 답하던 문제가 해결되고 /model로 소넷 5.5에서 오퍼스 5.5로, /effort로 추론 강도를 바꿀 수 있어요. 추론 강도는 높을수록 토큰을 많이 쓰는데, 투쏠은 맥스까지 갈 필요 없이 하이(high)면 대부분 충분하다고 봅니다.

가장 중요한 건 토큰을 아껴 주는 /compact와 /clear예요. 컨텍스트 윈도우(context window, 모델이 응답을 만들 때 한 번에 들고 가는 작업 메모리)는 대화가 쌓일 때 1:1로 늘지 않거든요. 이전 턴의 입력과 출력이 통째로 다음 턴 입력으로 넘어가서 비선형적으로 커지고 긴 답변과 큰 도구 출력이 다음 턴의 부담이 됩니다. 토큰이 늘면 정확도와 회상이 떨어지는 컨텍스트 부패(context rot)도 생겨요.

투두 앱을 "할 일·진행 중·완료가 한 화면에 다 보이게" 고친 뒤 /context로 확인하니 12%가 차 있었고 /compact로 압축하자 0%가 됐어요. 압축 후에도 "방금 뭘 요청했지?"라고 물으면 기억합니다. 이어서 드래그 앤 드롭 기능을 넣고 "CLAUDE.md 업데이트하고 handoff.md(인수인계 문서)에 진행 상황 적어"라고 시킨 뒤 /clear를 하면, 이번엔 이전 대화가 완전히 사라져요. /compact는 요약본이 남지만 /clear는 아무것도 남지 않아요. 그래서 handoff.md를 남겨 두는 겁니다.

그 밖에 자주 쓰는 명령어도 소개해요.

  • /btw: 클로드가 작업 중일 때 새 메시지를 보내면 작업이 끊기는데, 이 명령은 아래에 별도 창을 열어 작업을 멈추지 않고 "어디까지 했어?"를 물을 수 있어요.
  • Tab 키: 긴 슬래시 명령어는 목록에서 고른 뒤 Tab을 누르면 바로 입력됩니다.
  • /resume: 직전 작업을 이어서 볼 수 있어요.
  • /rewind(또는 ESC 두 번): 이상해진 작업을 이전 채팅 시점으로 되돌립니다.
  • /goal: 주어진 작업을 끝까지 해내게 만드는 명령이고 완료 조건을 정확히 정하는 게 핵심이에요.

MCP는 허브, 그중 컴포지오 하나면 앱 연결이 끝나요

MCP를 알려면 API부터 알아야 해요. 식당에서 손님(클라이언트)이 주문하면 웨이터가 주방(API 서버)에 전하고 음식을 가져오는데, 이 웨이터 역할이 API입니다. MCP(Model Context Protocol)는 맥북의 C타입 포트 하나에 5핀·8핀·HDMI를 다 꽂게 해 주는 허브와 같아요. 구글 드라이브만 해도 생성·수정·삭제·조회에 시트·문서용까지 수백 개 API가 있는데, MCP 서버 하나만 연결하면 이걸 일일이 붙이지 않아도 됩니다.

클로드 코드에서는 /mcp로 연결을 관리하고 클로드 앱에 이미 연결해 둔 MCP도 호환돼요. 투쏠이 유일하게 강력 추천하는 건 컴포지오(Composio)로, 여러 앱을 한데 묶어 주는 "MCP 중의 MCP"입니다. 구글 연동은 원래 구글 클라우드 콘솔에서 프로젝트를 만들고 API를 설정하는 등 번거로운데, 컴포지오에서는 Gmail을 검색해 Connect만 누르면 연결되고 한 서비스에 여러 계정도 붙일 수 있어요.

연결 순서는 단순해요. 컴포지오의 MCP 주소를 복사해 클로드 코드에 "MCP 서버 추가해 줘"라고 보내고 인식이 안 되면 클로드 코드를 껐다 켭니다. 그다음 /mcp에서 컴포지오를 골라 Authenticate로 접근을 허용하면 끝이에요. "컴포지오에서 구글 관련 제품 뭘 쓸 수 있어?"라고 물으니 Gmail·캘린더·시트·슬라이드·폼·미트·태스크·애널리틱스·유튜브가 나왔습니다. 투쏠은 이걸 클로드 코드에 팔을 달아 주는 것에 빗대요.

스킬은 에이전트에게 주는 반복 업무 매뉴얼이에요

스킬(Skill)은 반복 업무 절차서이자 에이전트용 작은 매뉴얼로, 메이크(Make)·n8n 같은 자동화 툴로 짜던 플로를 그대로 옮겨 온 개념이에요. 지휘자 역할의 SKILL.md(목표·입력·단계별 체크리스트)와 scripts(실제 실행 코드), references(결과가 어떻게 나와야 하는지 참고 자료), assets(필요한 파일)로 구성됩니다. 설명 한 줄만 먼저 읽고 본문은 필요할 때 읽어서 가벼워요. 자동화 툴과 달리 오류가 나도 에이전트가 스스로 고치거나 다른 방법을 찾아요. 스킬 안에 MCP를 넣어 함께 쓸 수도 있습니다.

먼저 깃허브의 Anthropic 공식 스킬 저장소에서 스킬 크리에이터(skill-creator)는 꼭 설치하라고 강조해요. 저장소 주소를 복사해 "이거 설치해 줘"라고만 하면 되고 MCP와 달리 스킬은 재시작 대신 스킬 새로고침(reload skills)을 해 주면 / 목록에 나타납니다.

스킬을 만들기 전에 권한 모드도 설명합니다. Shift+Tab으로 바꾸는데, 플랜 모드는 계획만 세우고, 기본 모드는 매번 "해도 될까요?" 승인을 받고, 바이패스 모드는 전부 알아서 하고, 오토 모드는 민감한 건 빼고 알아서 해요. 투쏠은 바이패스보다 오토 모드를 쓰고, 작업은 플랜 모드로 먼저 계획을 세운 뒤 시작하길 권합니다.

실습으로 "웹 정보를 찾아 요약한 뒤 컴포지오로 내 Gmail에 보내 주는 스킬"을 플랜 모드에서 요청해요. 클로드가 SKILL.md·references·scripts로 된 디렉터리 계획을 보여 주고 확인 후 엔터를 누르면 구현과 테스트까지 끝내 "웹 다이제스트 메일러" 스킬이 만들어집니다. /clear 후 이 스킬로 젠슨 황 뉴스를 요청하니 크롤링 도구 파이어크롤(Firecrawl)로 수집·정리해 HTML 카드형 메일이 원문 링크와 함께 도착했어요. 슬래시 명령으로 부를 수도 있고 "같은 스킬로 오픈AI 조사해"처럼 말로 부를 수도 있습니다.

스킬도 한 번에 완벽해지지 않아요. 기존 SOP나 체크리스트를 정리해 스킬 형식으로 변환을 요청하고 SKILL.md와 스크립트를 쓰고 테스트하고 반영하는 과정을 반복해야 합니다. "잘 써 줘"가 아니라 판단 기준을 주는 게 중요하다고 해요. 또 스킬을 설치할 때 묻는 글로벌(global)은 어느 폴더에서나 쓰는 것, 프로젝트(project)는 그 폴더 안에서만 쓰는 것이라 꼭 구분해야 합니다. 회의록 요약, 이메일 라벨링, 리드 스크래핑, 계약서·청구서 작성 같은 업무가 스킬 후보로 꼽혀요.

서브에이전트는 별도 공간에서 일하고 결과만 돌려줘요

세션이 길어지면 컨텍스트가 오염돼 이상한 결과가 나올 확률이 커져요. 서브에이전트(subagent)는 일을 별도 작업 공간에 위임해서 부모 컨텍스트와 분리된 곳에서 작업한 뒤 결과만 메인으로 가져옵니다. 에이전트도 MD 파일로 만들고 name·description·tools·model을 정하며 프로젝트 폴더의 .claude/agents/ 아래 code-reviewer·test-runner 같은 MD 파일 하나하나가 에이전트예요. 에이전트에게 스킬을 쓰도록 지정할 수도 있습니다.

실습에서는 앞서 만든 웹 다이제스트 스킬을 참고해 컴포지오 도구까지 쓰는 리서치 에이전트를 플랜 모드로 만들어요. 클로드가 매일 발송 여부, MD 리포트 저장, 모델(소넷·오퍼스) 등을 되묻고 투쏠은 오퍼스를 고릅니다. 이때 "설계 디렉터리부터 보여 줘"라고 해서 구조 지도를 꼭 확인하라고 해요. 구현 후 폴더 구성이 부족해 "이 폴더를 아예 에이전트용으로 바꿔"라고 한 번 더 고쳤고 에이전트를 실행하자 메인 세션이 아닌 별도 공간에서 작업이 돌아갔습니다.

작업 중 새 메시지를 보내면 에이전트가 멈추니, 진행 상황은 /btw로 물어보면 돼요. 결과는 "AI 에이전트 동향" 브리핑 메일로 도착했습니다. 스킬은 메인 세션에서 정해진 절차를 빠르게 처리하고 서브에이전트는 백그라운드에서 스스로 판단하며 메인 컨텍스트를 아껴 준다는 게 둘의 차이예요. 마무리로 /init을 실행해 이 폴더가 "서브에이전트 전용 작업 폴더"라는 CLAUDE.md도 만들어 둡니다.

서브에이전트가 잘 맞는 일은 같은 처리를 많이 반복할 때, 대규모 코드 리뷰, 병렬 리서치, 여러 디자인을 동시에 만들 때예요. 반대로 단순 수정, 작은 질문, 한 번에 끝나는 작업, 사용량을 아껴야 하는 작업, 앞 단계 결과가 있어야 다음이 되는 순차 작업에는 맞지 않습니다. 에이전트는 많을수록 좋은 게 아니라서 한 프로젝트에 5~10개가 가장 좋고 50개씩 만드는 건 비추천이라고 해요.

훅은 100% 실행되는 자동 장치, 그리고 창시자의 사용법

훅(Hook)은 정해진 순간에 내 스크립트를 99%도 아닌 100% 자동 실행하는 장치예요. 물고기가 낚싯바늘을 물면 바로 건져 올리듯, 특정 행동 전후에 무조건 동작합니다. CLAUDE.md의 "하지 마"는 충돌하면 무시될 수 있고 모델 판단에 기대지만 훅은 모델이 아니라 내 스크립트가 검사하고 차단해요. 바이패스 모드에서 클로드가 D 드라이브를 통째로 지운 사고가 있었는데, CLAUDE.md에 금지를 적는 것보다 접근하는 순간 튕겨 내는 훅이 확실하다는 예시를 듭니다. 세션 시작·종료, 프롬프트 입력 전, 도구 호출 전후 같은 시점에 걸 수 있어요.

실습에서는 투두 앱의 "완료 항목 지우기" 버튼을 노란색으로 바꾸고 handoff에 기록한 뒤, 매번 "handoff 업데이트해", "handoff 읽고 어디서부터 할지 알려줘"라고 시키는 게 불편하다는 데서 출발해요. 그래서 앱을 고치면 handoff.md를 자동 업데이트하는 훅, 세션 시작 시 handoff.md를 자동으로 읽는 훅 두 가지를 말로 요청합니다. 훅은 settings.json에 SessionStart·PostToolUse·Stop 같은 이벤트별로 저장되고 바로 적용되지 않으면 클로드 코드를 껐다 켜야 해요.

처음엔 원하는 형태가 아니어서 "어떤 메시지를 입력하든 답변 맨 앞에 뭘 해야 할지 짧게 알려 줘"로 고쳤더니, /clear 후 첫 질문에 "투두 작업 중, 완료 항목 노란 버튼으로 변경"이라는 현황이 먼저 나왔어요. 이어서 완료 칸 아래 드래그하면 사라지는 삭제 바구니를 추가하자, 따로 말하지 않았는데도 handoff.md가 자동으로 업데이트됐습니다. 작업이 끝날 때마다 검수·테스트 에이전트를 부르는 것처럼 에이전트를 훅에 엮는 것도 가능해요.

마지막은 클로드 코드를 만든 보리스 체르니(Boris Cherny)의 사용법이에요. 창을 여러 개 나눠 클로드 코드를 동시에 돌리고 질문이 있을 때만 알림을 받으며 완료된 작업은 거의 검수하지 않는다고 합니다. 노트북을 닫아도 클라우드(웹)에서 계속 돌리고 중요한 일은 페이블·오퍼스 5.5, 단순 구현은 하이쿠·소넷 5.5처럼 모델을 나눠 써요. 실수를 볼 때마다 지침에 한 줄씩 추가하고 거의 모든 작업을 계획 모드로 시작하며 코드를 정리하는 담당과 제대로 됐는지 확인하는 담당 보조 에이전트를 둡니다. 전부 허용은 쓰지 않고 "권한은 좁게, 연결은 넓게"가 원칙이에요.

쓰는 방법은 셋 다 같은 클로드 코드예요. IDE 확장(익스텐션에서 Claude Code for VS Code 설치)에서는 Shift+Enter 줄바꿈이 되고 클로드 앱에서는 "이 컴퓨터"와 "클라우드" 중 골라 실행할 수 있습니다. 투쏠은 코덱스와 클로드를 여러 창에 띄워 동시에 쓰려고 터미널을 고집하지만 앱이 편하면 앱으로 해도 된다고 해요. 그리고 강의 속 에이전트를 그대로 쓰기보다 그 구조를 참고해 나에게 맞는 에이전트를 직접 설계해 보라고 당부하며 마무리합니다.

핵심 인사이트

  • CLAUDE.md는 권고, 훅은 강제: CLAUDE.md는 짧게 유지해도 100% 지켜지지 않으니, 반드시 지켜야 하는 규칙과 매번 반복할 일은 훅으로 고정해야 해요. "사람이 매번 하던 일을 규칙으로 고정한다"는 게 훅의 쓰임입니다.
  • 컨텍스트는 비선형으로 불어나요: 이전 입출력이 매 턴 통째로 다시 들어가니, /compact·/clear와 handoff.md 인수인계 문서를 함께 써야 긴 작업에서도 품질이 유지돼요.
  • 스킬과 서브에이전트는 쓰임새가 달라요: 정해진 절차를 메인 세션에서 빨리 돌리려면 스킬, 병렬·대량 작업을 백그라운드에서 맡기고 메인 컨텍스트를 아끼려면 서브에이전트가 맞아요. 에이전트는 프로젝트당 5~10개가 적정이에요.
  • MCP는 클로드에게 팔을 달아 주는 일이에요: 컴포지오 같은 허브형 MCP 하나면 Gmail·캘린더·시트 등을 복잡한 API 설정 없이 붙일 수 있고 이를 스킬 안에 넣어 실제 업무 자동화로 이어 갈 수 있어요.

오늘 당장 해볼 것

  1. 작업 폴더에서 claude를 실행하고 /init으로 CLAUDE.md를 만든 뒤, 매번 하던 지시 3~5개를 불릿으로 추가해 보세요. 새 세션에서 같은 요청을 했을 때 결과가 일관되게 나오는지 바로 확인할 수 있어요.
  2. 긴 작업이 끝날 때마다 "handoff.md에 진행 상황 적어"를 시킨 뒤 /clear로 컨텍스트를 비워 보세요. 대화를 지워도 다음 세션이 어디서 이어 갈지 알게 됩니다.
  3. Anthropic 스킬 저장소에서 skill-creator를 설치하고 플랜 모드(Shift+Tab)로 "주제를 받아 웹에서 찾아 요약하고 메일로 보내는 스킬"처럼 내 반복 업무 하나를 스킬로 만들어 보세요. 계획 단계에서 디렉터리 구조를 먼저 보면 실패가 줄어요.
  4. 컴포지오에 Gmail·캘린더를 연결하고 MCP 주소를 클로드 코드에 추가해 보세요. 구글 클라우드 콘솔 설정 없이 메일 발송까지 한 번에 붙일 수 있어요.
  5. "세션 시작 시 handoff.md를 읽고 할 일을 맨 앞에 알려 주는 훅"을 말로 요청해 settings.json에 걸어 보세요. 매번 현황을 묻지 않아도 돼서 체감이 가장 큰 훅이에요.
