Gemini 4 Argon vs Opus 5.5, 같은 앱 만들기 대결 (날것 그대로)

출처 · Jack Roberts이 글은 아래 영상 내용을 한국어로 요약·정리한 것입니다. 원문의 주장과 수치는 영상 제작자의 것입니다.원제 · New Gemini 4 Argon vs Opus 5.5 Building the Same App (Raw Results)

핵심
  • 벤치마크 1위가 실전 1위는 아니에요
  • 토큰 효율은 '한 번에 끝날 때'만 의미가 있어요
  • 모델만큼 하네스가 중요해요

한 줄 요약

벤치마크 70% 이상에서 Opus 5.5를 앞섰다는 Gemini 4 Argon을 같은 프롬프트로 7단계 과제에 붙여 봤더니, Jack Roberts의 판정은 일곱 번 모두 Claude 승이었어요. 다만 토큰은 Argon이 400만, Claude가 2200만을 써서 비용 효율만큼은 Argon 쪽이 확실히 앞섰습니다.

전체 내용 정리

벤치마크 1위 모델, 실제로 써 보면 어떨까요?

Google이 내놓은 Gemini Argon 4는 벤치마크의 70% 이상에서 Opus 5.5를 앞섰고 18개 일반 벤치마크 중 12개에서 1위를 차지했어요. 그런데 Jack은 "벤치마크 따위엔 관심 없고 실제 결과가 중요하다"는 입장이에요. 그래서 두 모델에 똑같은 프롬프트를 주고 웹사이트, 앱, 게임, 리버스 엔지니어링(reverse engineering) 사례까지 7단계 난이도로 돌려 봤습니다. 걸린 시간과 비용도 함께 공개했는데 Jack 말로는 결과가 "결코 비슷하지 않았다"고 해요.

Argon은 지금 Gemini 앱에서 바로 쓸 수 있어요. Claude와 비슷하게 생긴 Google의 통합 개발 환경(IDE) Antigravity를 내려받아도 되고, API로 붙여도 됩니다. 이미지·영상 생성은 공정하게 두 모델 모두 Higgsfield API 하나로 통일했어요. API 키만 넘겨 주고 필요한 에셋은 모델이 알아서 만들게 한 방식이죠.

레벨 1·2, 향수 웹사이트와 15초 애니메이션은 Claude가 가져갔어요

첫 과제는 향수 브랜드 웹사이트를 프롬프트 한 줄로 만드는 거였어요. Gemini 결과물은 배경 영상 덕분에 깊이감이 있었고 이미지 생성도 훌륭했지만 처음 봤을 때 AI 느낌이 조금 난다는 평이었죠. Claude 쪽은 파도가 바위에 부딪히는 배경 영상에 연기 효과까지 얹고 향수를 화면의 주인공으로 잘 살렸어요. Claude는 약 30분, Gemini는 18분이 더 걸렸습니다. 토큰 비용은 Gemini가 훨씬 저렴했지만 성능 차이 때문에 Jack은 Claude를 골랐어요.

레벨 2는 습관 추적기(habit tracker)용 15초짜리 제품 소개 애니메이션이에요. Argon 결과도 꽤 인상적이었지만 AI 느낌이 살짝 나고 G 글자 아래쪽이 잘리는 문제가 있었죠. Opus 5.5는 로고 애니메이션을 포함한 인트로가 "말도 안 될 정도"로 좋아서 Jack은 Argon보다 확실히 한 단계 위라고 평가했습니다. Argon이 조금 더 빨리 끝냈고 가격도 훨씬 저렴했지만 실제 성능에서는 Claude가 확실한 승자라고 봤어요.

중간에 Jack이 짚은 팁이 하나 있어요. Argon을 쓴다면 OpenRouter 말고 Antigravity 앱 안에서 쓰라는 거예요. OpenRouter에서 Gemini 4를 쓰면 Antigravity 하네스(harness, 모델을 감싸 작업을 돌려 주는 실행 환경)를 거치지 않거든요. 실제로 API로 처음 돌린 몇몇 작업은 결과가 충분히 좋지 않았고 Google 하네스로 다시 돌린 다음에야 괜찮은 결과가 나왔다고 해요.

좋은 하네스를 쓰지 않으면 결과가 떨어지는 건 Claude도 마찬가지라는 게 Jack의 설명이에요. 모델 이름만큼이나 어디서 돌리느냐가 결과를 좌우한다는 얘기죠.

레벨 3·4, 마인크래프트 게임과 브라우저 포토샵은 접전이었어요

레벨 3은 3D 물리 엔진과 조작까지 갖춘 마인크래프트 스타일 복셀 월드(voxel world)를 파일 하나로 처음부터 만드는 과제였어요. 1인칭으로 걷고 블록을 부수고 낮과 밤이 바뀌는 세계죠. Gemini는 약 35분, 대략 5달러로 블록 배치까지 되는 그럴듯한 게임을 만들었습니다. Claude 결과물도 매우 비슷했지만 색감 보정이 조금 더 나아서 Jack은 근소하게 Claude 손을 들어 줬어요.

레벨 4는 별(star)이 거의 30만 개 달린 GitHub 저장소 '무엇이든 역공학(reverse engineer)'을 두 모델에게 쥐여 주고 "브라우저에서 작동하는 사진 편집기를 만들어 줘"라고 요청한 과제예요. 이 저장소는 어도비 제품군 전체를 역공학으로 분석해 낸 적도 있다고 하죠. Gemini가 만든 Luminar Pro는 밝기·대비·채도 조절, 필터, 회전·자르기, 브러시, 레이어 섹션까지 갖춘 꽤 포토샵다운 편집기였어요.

Opus 5.5 쪽은 조정 기능이 약간 적은 대신 필터가 더 좋아 보였고 인터페이스가 훨씬 간결하고 선명했어요. Jack은 "기능은 Argon이 조금 더 많지만 전반적인 사용자 경험(UX)은 Claude가 낫다"고 정리했습니다. 토큰당 결과물은 Argon이 훨씬 뛰어났고 완성도는 50 대 50으로 봤지만 UI 때문에 이번에도 Claude 승이에요.

레벨 5·6, 나를 위한 앱과 대시보드 개선은 디자인에서 갈렸어요

레벨 5는 일부러 정보를 거의 주지 않은 개인화 과제였어요. Jack에 대한 짧은 요약만 주고 "내가 쓰기 편한 걸로 하나 만들어 봐"라고 했죠. 최소한의 문맥으로 얼마나 잘 해내는지가 모델 실력을 보는 좋은 방법이라는 게 Jack의 생각이에요. Gemini가 만든 '그린 라이트 운영체제'는 패키징, 덱·에셋 스튜디오, 스폰서 승인, 썸네일 대기열까지 기능 방향은 맞았어요. 하지만 모든 요소가 관심을 끌려고 싸우는 화면이라, Jack은 "계층 구조(hierarchy)라는 말 들어 본 적 있냐"고 혹평했습니다.

Claude는 모든 걸 이번 주 단위로 정리해 주고 항목을 직접 옮길 수 있는 구조에 이미지 생성까지 해 줬어요. 여전히 조금 복잡하긴 해도 훨씬 이해하기 쉬워서 이견 없는 Claude 승이었죠.

레벨 6은 Jack이 쓰는 에이전트 운영체제(Agentic OS) Jarvis에 기능을 추가하는 과제예요. Jarvis는 Claude, ChatGPT, Codex를 한곳에서 관리하고 Grok 봇·Hermes 봇 같은 에이전트와 메모리 시스템을 갖춘 대시보드죠. "전권을 줄 테니 흥미롭고 독특한 걸 찾아 줘"라고 맡겼더니, 두 모델 모두 제작 현황을 보여 주는 뷰를 만들었어요. Gemini 쪽은 썸네일이 안 끝나 보류된 영상을 짚어 줬지만 디자인이 다소 복잡했어요. Opus 5.5는 녹화·덱 작업 진행 상황을 한눈에 볼 수 있어 시각 디자인이 살짝 더 나았습니다. 시간은 Gemini가 더 걸렸지만 토큰은 3분의 1밖에 안 썼어요.

레벨 7, 썸네일 디자인은 둘 다 아쉬웠어요

마지막은 이 영상의 썸네일을 디자인하는 과제였어요. 좋은 유튜브 영상과 썸네일이 무엇인지 이해해야 해서 가장 창의력이 필요한 단계죠. Gemini 결과물은 Jack 말로 "제정신이 아닌" 수준이었지만 주변에 작은 시스템을 만들고 티저 예고편까지 붙인 점은 흥미로웠다고 해요. Opus는 분할형 썸네일 몇 가지와, 두 공이 서로 공격하다 폭발하고 하나만 살아남는 영화 예고편 같은 애니메이션을 만들었어요.

둘 다 Jack을 감동시키지는 못했어요. 프롬프트가 사실상 "AI와 좋은 썸네일의 요소를 조사해서 뭔가 만들어 봐" 수준이었으니까요. 그래서 Jack은 좋은 프롬프트를 쓰려면 때로는 좋은 지식이 먼저 필요하다고 봅니다.

결과는 7전 7승 Claude, 그런데 토큰은 5배 넘게 차이 났어요

Jack의 결론은 Claude가 일곱 번 모두 이겼다는 거예요. 그중 하나는 조금 의구심이 들었다고 덧붙였죠. Antigravity가 깔끔하고 재미있어서 Argon 4가 이기길 진심으로 응원했다는 고백도 했어요.

숫자로 보면 Argon이 400만 토큰, Claude가 2200만 토큰을 썼습니다. Gemini의 토큰 효율이 더 좋은 건 분명하지만 Jack은 나중에 수정하고 다듬으며 수천 번 방향을 틀어야 할 때는 그 토큰 효율이 무의미해진다고 봐요. 요금제 얘기도 했는데, 100달러 요금제와 Google AI Ultra 200달러 요금제를 비교하면 가격은 두 배지만 사용량은 4배를 얻는 셈이라고 설명했어요. 오늘 앱들을 만드는 데는 100달러 요금제 기준으로 주간 사용량의 25%밖에 들지 않았다고 하고요. 참고로 Argon은 Ultra 요금제에서만 쓸 수 있고 Pro 요금제에는 포함되지 않아요.

그래서 Jack의 조언은 이래요. 지금 당장 Opus 5.5나 ChatGPT를 떠날 이유는 없습니다. 벤치마크가 실제로는 큰 의미가 없다는 걸 확인했대요. Argon은 백그라운드에서 무난하게 돌아갈 상위 중위권 모델이지만 Opus 5.5가 있는 최첨단 수준에는 아직 못 미친다는 평가예요.

핵심 인사이트

  • 벤치마크 1위가 실전 1위는 아니에요: 벤치마크 70% 이상에서 앞선 Argon이 Jack의 판정으로는 실제 7개 과제에서 한 번도 이기지 못했어요. 모델을 고를 때는 순위표보다 내 업무와 비슷한 과제로 직접 돌려 보는 편이 정확하다는 걸 보여 줍니다.
  • 토큰 효율은 '한 번에 끝날 때'만 의미가 있어요: Argon은 토큰을 Claude의 5분의 1 이하로 썼지만 Jack은 나중에 수정하고 다듬으며 수천 번 방향을 틀어야 할 때는 그 효율이 무의미해진다고 봐요. 토큰 숫자만으로 비용을 판단하기 어렵다는 얘기죠.
  • 모델만큼 하네스가 중요해요: 같은 Gemini 4라도 OpenRouter API로 돌렸을 때와 Antigravity 하네스로 돌렸을 때 결과가 달랐어요. Claude도 마찬가지라고 하니, 성능 비교 전에 어떤 실행 환경에서 돌리는지부터 맞춰야 합니다.

오늘 당장 해볼 것

  1. 지금 쓰는 AI로 자주 하는 업무 하나(견적서 초안, 고객 응대 템플릿 등)를 골라 두 모델에 똑같은 프롬프트로 돌려 보세요. 벤치마크 기사보다 내 업무에서 누가 나은지가 훨씬 빨리 보입니다.
  2. 작업 하나를 끝낼 때마다 걸린 시간과 수정 횟수를 메모해 보세요. 수정이 쌓이면 토큰 효율이 무의미해진다는 Jack의 관점이 내 업무에서도 맞는지 숫자로 확인할 수 있어요.
  3. 원하는 결과가 안 나오면 프롬프트에 판단 기준을 먼저 넣어 보세요. 레벨 7처럼 "좋은 썸네일이 뭔지"를 모델에게 맡기면 엉뚱한 결과가 나오기 쉬우니, 참고 예시나 체크리스트를 같이 주면 결과가 달라집니다.
