옵시디언 버리고 이걸로 갈아탑니다

출처 · 투쏠ㅣAI 에이전트이 글은 아래 영상 내용을 한국어로 요약·정리한 것입니다. 원문의 주장과 수치는 영상 제작자의 것입니다.

핵심
  • 팀 지식 공유의 핵심은 '공유'보다 '권한'이에요
  • 사람의 권한이 그대로 AI의 권한이 돼요
  • 도구 하나를 깊게 익히면 다음 도구는 인터페이스만 바뀐 것이에요

한 줄 요약

혼자 쓰던 옵시디언 LLM 위키를 팀원과 나눠 쓰고 싶은데, 보여 주면 안 되는 문서까지 AI가 읽어 버릴까 걱정이라면 이 영상이 답이에요. 투쏠이 폴더 단위 권한과 MCP 연결을 함께 제공하는 팀용 세컨드 브레인 '발다'를 설치부터 Claude 연결, 권한 차단 확인까지 직접 보여 줘요.

전체 내용 정리

혼자 쓰던 LLM 위키를 팀이 쓰려니 막혔어요

5인 미만 작은 조직이라면 어떤 자료를 공유하고 누구에게 어디까지 수정을 맡길지 고민이 생기죠. 투쏠은 많은 대표님들이 이걸 자주 묻는다고 말해요. 옵시디언으로 LLM 위키를 만들어 쓰고 있는데 이걸 팀원도 쓰게 하고 싶다는 질문이 특히 많았대요. RAG나 온톨로지까지 가지 않고 LLM 위키 수준에서 팀 브레인을 해결할 수 없냐는 질문도 많았대요.

혼자 쓸 때는 아무 문제가 없었어요. 내 지식을 쌓아 Claude, Codex, Hermes, OpenClaw 같은 도구에 연결하고 AI와 함께 찾고 묻는 작업이 다 됐거든요. 그런데 팀으로 넓히려니 질문이 생겨요. 어디까지 열어 둬도 될까? 누가 어떤 문서를 볼 수 있고 누가 원본을 바꿔 버리면 어떻게 되고 "읽지 마"라고 해도 AI가 우회하면 어쩌나 하는 것들이죠.

예를 들면 이런 상황이에요. 회사에 C레벨 임원이 있고 팀 브레인을 AI에 연결했을 때, C레벨용 문서는 C레벨만, 그리고 그 사람의 AI만 볼 수 있게 하고 싶은 거죠. AI에게 "이건 보지 마"라고 훅(hook)으로 걸어 둘 수도 있지만 한 치의 오류가 생길 수 있다고 투쏠은 짚어요.

공유와 권한을 함께 갖춘 팀용 세컨드 브레인, 발다는 팀원 10명까지 무료예요

그래서 투쏠이 소개하는 도구가 발다예요. 메인 슬로건부터 "팀 세컨드 브레인", 오직 조직을 위한 세컨드 브레인이라고 내걸고 있어요. 오픈소스이면서 호스팅도 기본으로 제공해요.

내려받아 실행하면 새 볼트 만들기, 기존 볼트 열기, 팀 참여하기 세 가지 선택지와 구글 로그인이 나와요. 로그인하면 옵시디언과 아주 비슷한 화면이 보여요. 옵시디언은 패널이 왼쪽에 있는데 발다는 오른쪽 위에 있다는 정도가 달라요. 옵시디언 그래프 뷰처럼 생긴 '그래프' 아이콘도 있어서 처음 보면 "똑같은 옵시디언인데 디자인이 좀 별로다"라고 느낄 수도 있대요.

문서 구조도 같아요. 위키 폴더에 들어가 문서를 열면 옵시디언처럼 마크다운 파일이 폴더에 저장돼 있어요. 왼쪽 위를 누르면 볼트를 고를 수 있어서 투쏠은 원래 쓰던 개인 볼트 '세컨드 브레인'도 넣고 따로 작업 중인 팀 볼트도 넣어 쓰고 있대요.

볼트 설정의 결제 항목을 보면 프로로 업그레이드할 때 한 달에 1만 2천 원 정도가 든대요. 그런데 팀원이 10명이 될 때까지는 전부 무료예요. 투쏠은 Slack처럼 팀원이 늘수록 비용이 계속 늘어나는 구조가 아니라는 점을 장점으로 꼽아요. 한 번 결제하면 팀원 수 제한 없이(unlimited team members) 계속 추가할 수 있대요.

진짜 핵심은 MCP예요

설정 화면 아래쪽에 MCP 항목이 있는데 투쏠은 "이게 진짜"라고 말해요. 발다 서버에 있는 MCP를 연결해 두면 인터넷에서 쓰는 Claude나 GPT, Codex 같은 AI가 내 세컨드 브레인을 볼 수 있거든요. 팀원에게 이 MCP를 공유하면 팀원의 AI도 같은 브레인을 쓰게 되고요.

폴더 단위로 막아 두면 팀원 화면에선 비어 보여요

설정의 '멤버 및 접근(Members & Access)'에서 권한을 줘요. 팀원을 초대한 뒤 '접근 관리(Manage Access)'를 누르면 그 사람에게 어떤 볼트가 보일지 정할 수 있어요. 볼트 전체를 통제하게 할지, 편집하게 할지, 아니면 'context'나 'skills' 같은 특정 폴더를 보기만 하게 할지, 아예 접근을 막을지를 세세하게 고를 수 있대요. 폴더 안의 하위 폴더까지 골라서 설정할 수 있고요.

초대도 간단해요. 같은 메뉴에서 '사람 초대(Invite People)'를 누르면 공유용 참여 코드가 나오고 이 코드를 특정 사람에게 주면 팀원으로 들어와요.

투쏠은 실제로 막히는지 확인해 봐요. 먼저 '투솔'이라는 팀원이 context와 daily 두 폴더를 볼 수 없게 설정해 둬요. 그다음 팀원 계정으로 로그인하면 볼트 설정에서 자기 역할이 소유자(owner)가 아니라 멤버로 표시돼요.

프로젝트, 인사이트, 위키 같은 폴더는 다 보여요. 그런데 context 폴더를 누르면 '비어 있음(empty)'이라고 나와요. daily도 마찬가지예요. 권한이 없으면 팀원 화면에서는 아예 볼 수가 없는 거죠.

Claude 웹에 연결해도 AI가 막힌 폴더를 못 읽어요

이제 AI 쪽에서도 막히는지 확인해요. 연결 순서는 이래요.

  1. 발다 볼트 설정의 MCP 항목에서 '토큰 만들기(Create Token)'를 눌러 접근 토큰을 발급받아요.
  2. 같은 화면의 MCP 서버 주소를 복사해요.
  3. 데스크톱 앱이 아니라 웹 버전 Claude에서 설정 → 커넥터 → 추가 → 커스텀 커넥터 추가로 들어가요.
  4. 이름은 '조직 브레인'으로 하고 MCP 서버 주소를 붙여 넣어요.
  5. 팀원은 접근 토큰도 넣어야 해요. 헤더 이름에서 접근 토큰 항목을 고르고 값에 발다에서 복사한 토큰을 붙여 넣은 뒤 추가를 누르면 연결이 끝나요.

연결된 조직 브레인으로는 첨부 목록, 폴더 목록 보기, 쓰기, 삭제까지 다 할 수 있대요. 다만 멤버는 앞서 설정한 대로 기능이 제한돼요. Claude에게 "조직 브레인 연결했으니 확인해 볼래?"라고 묻자 연결 상태가 정상이라는 답이 돌아와요. 이어서 "context하고 daily 폴더가 있을 텐데 확인해 볼래?"라고 묻자, Claude는 두 폴더가 있다는 건 보이지만 안에 있는 노트는 하나도 안 보이고 계정에 잠겨 있다고 답해요. 회사의 세컨드 브레인을 통째로 줘도 권한이 없는 팀원과 그 팀원의 AI는 막힌 문서를 볼 수 없다는 게 확인된 거죠.

이런 식으로도 응용해 볼 수 있어요

투쏠은 앞으로 해 볼 만한 구성도 하나 제안해요. 구글 계정이 여러 개라면 계정마다 에이전트를 하나씩 만들고 A 레벨만 쓰는 A 에이전트, B 레벨만 쓰는 B 에이전트, C 레벨만 쓰는 C 에이전트처럼 에이전트별로 접근 권한을 나눠 주는 방식이에요.

데이터가 발다에 띄워진 MCP 서버로 흘러가는 게 꺼려지는 분도 있을 거예요. 그럴 때는 오픈소스 버전을 내려받아 카페24, Railway, Cloudflare 같은 곳에 직접 호스팅하고 그걸 MCP로 만들어 올리면 된다고 해요.

마지막으로 투쏠은 요즘 도구들이 다 비슷하다고 느낀대요. 옵시디언을 제대로 배워 두니 발다도 인터페이스만 다를 뿐 크게 다르지 않았다고요. Claude Code와 Codex, Hermes도 하나를 제대로 익혀 두면 나머지는 인터페이스만 바뀐 것처럼 쓸 수 있다는 걸 최근 많이 느낀다고 말해요.

핵심 인사이트

  • 팀 지식 공유의 핵심은 '공유'보다 '권한'이에요: 혼자 쓰던 위키를 팀으로 넓히려니 어디까지 열어 둘지가 막혔다는 질문이 많았대요. 투쏠은 AI에게 훅으로 "보지 마"라고 걸어 두면 한 치의 오류가 생길 수 있다고 보고, 폴더 단위 권한을 나누는 발다를 대안으로 보여 줘요.
  • 사람의 권한이 그대로 AI의 권한이 돼요: 발다는 팀원이 자기 Claude에 연결해도 그 팀원이 못 보는 폴더는 AI도 못 읽게 막아요. 투쏠이 직접 팀원 계정과 Claude 웹으로 두 번 확인해 보인 부분이 바로 이거예요.
  • 도구 하나를 깊게 익히면 다음 도구는 인터페이스만 바뀐 것이에요: 투쏠은 옵시디언을 제대로 배워 두니 발다로 바로 넘어갈 수 있었다고 말해요. Claude Code와 Codex, Hermes도 하나를 제대로 익히면 나머지는 크게 다르지 않다고 봐요.

오늘 당장 해볼 것

  1. 지금 쓰는 옵시디언이나 노션 자료를 "팀 전체 공개 / 일부만 / 나만" 세 칸으로 나눠 폴더 목록을 적어 보세요. 발다 같은 도구를 쓰든 안 쓰든 이 분류가 먼저 있어야 권한을 설계할 수 있어요.
  2. 팀원이 10명 미만이라면 발다를 내려받아 테스트용 볼트를 만들고 폴더 하나를 막은 팀원 계정으로 들어가 정말 비어 보이는지 확인해 보세요. 무료 범위 안에서 권한 구조를 직접 검증할 수 있어요.
  3. 웹 버전 Claude의 설정 → 커넥터 → 커스텀 커넥터에서 MCP 서버를 연결해 보고 막아 둔 폴더를 일부러 물어보세요. AI가 권한을 정말 지키는지 한 번 확인해 두면 사내 문서를 연결할 때 안심이 돼요.
