Grok Bot, 진짜다 — 알아야 할 것만

출처 · Nate Herk | AI Automation이 글은 아래 영상 내용을 한국어로 요약·정리한 것입니다. 원문의 주장과 수치는 영상 제작자의 것입니다.원제 · Grok Bot is For Real. What You Need to Know.
원본 영상 보기 →
핵심
  • 에이전트별 전용 컴퓨터가 반복 업무 자동화의 핵심이에요
  • 이름·타이틀·설명만으로 에이전트 간 업무 위임이 자동 작동해요
  • 트리거 자동화 설정 속도가 기존 노코드 도구보다 훨씬 빨라요

한 줄 요약

새로 나온 AI 에이전트 앱 그록 봇을 다룬 영상이에요. 폰과 PC에서 완전히 동기화되는 여러 에이전트를 만들어 각자 전용 컴퓨터로 반복 업무를 처리하게 하고, 시간·이벤트 기반 자동화까지 프롬프트 한 줄로 만들 수 있는 도구입니다.

전체 내용 정리

여러 대의 AI 에이전트를 폰과 PC에서 동시에 굴리는 앱이 나왔어요

그록 봇은 윈도우, 맥, iOS에서 모두 설치할 수 있고, 하나의 계정으로 로그인하면 대화 내용과 작업 상태가 실시간으로 동기화됩니다.

화면 왼쪽에 여러 에이전트를 나란히 두고 각각과 개별적으로 대화할 수 있으며, 에이전트끼리 서로 메시지를 주고받게 만드는 것도 가능해요.

처음 앱을 열면 첫 에이전트를 만들도록 안내하는데, 이름과 색상, 모양을 정하는 정도로 설정이 끝납니다.

이 도구를 쓰려면 커서 얼트라 플랜에 가입해야 하며, 영상 후반부에서는 같은 도구를 허메스 에이전트라는 이름으로도 불러요.

에이전트마다 자기만의 컴퓨터가 있어서 브라우저를 대신 조작해요

각 에이전트 설정 화면 오른쪽에서는 이름, 타이틀, 설명과 함께 그 에이전트가 쓰는 전용 컴퓨터 화면을 볼 수 있습니다.

예시로 든 에이전트 클라우스는 스쿨 커뮤니티에 본인 계정으로 로그인된 상태로, 지정한 게시물에 좋아요를 누르는 작업을 스스로 수행하고 있었어요.

사용자가 직접 그 컴퓨터 화면에 들어가 유튜브에 로그인하거나 캡차를 통과하는 것도 가능하고, 파일 관리자와 터미널도 열 수 있습니다.

"티치 어 태스크" 버튼을 누르면 사람이 직접 하는 작업을 녹화해서 그록 봇이 그대로 스킬로 만들어줘요. 이렇게 만든 스킬 중 하나가 스쿨 커뮤니티에 7일 챌린지 게시물을 올리는 작업이었습니다.

깃허브 저장소를 연결해두면 모든 에이전트가 그 저장소에 담긴 맥락을 공유해서, 매번 처음부터 설명하지 않아도 돼요.

에이전트마다 이름과 역할을 정해두면 서로 알아서 업무를 나눠줘요

새 에이전트를 만들면 무엇을 도와줄지 물어보는 온보딩 절차를 거칩니다.

예시로 클라우스는 비서 역할, 데브는 AI 엔지니어 역할을 맡았는데요. 클라우스에게 제품 개발을 요청하면 클라우스가 알아서 데브에게 작업을 위임해요.

여기서 재미있는 점이 있습니다. 에이전트를 만들 때 붙이는 이름, 타이틀, 설명은 다른 에이전트가 스킬을 찾아 쓰는 방식과 똑같이 작동해요. 한 에이전트가 처리할 수 없는 일이 생기면, 설명이 일치하는 다른 에이전트에게 메시지를 보내 대신 처리하게 합니다.

지메일, 구글 캘린더, 슬랙, 구글 드라이브, 클릭업 같은 서비스는 플러그인으로 연결하는데요. 한 에이전트에서 한 번 연결해두면 모든 에이전트가 같은 연결을 공유해서 쓸 수 있어요.

아침 브리핑 루틴을 프롬프트 한 줄로 만들어 매일 자동 실행시켰어요

새 에이전트를 아침 플래너로 설정하면서 지메일과 구글 캘린더를 연결하고, 평일 오전 7시에 오늘 일정과 지메일에서 처리할 항목을 정리해달라고 요청했습니다.

이렇게 만든 루틴은 클라우드에서 실행되기 때문에, 컴퓨터나 폰이 꺼져 있어도 정해진 시간에 작동해요.

실제로 받은 샘플 결과가 꽤 알차요. 그날의 미팅 목록, 답장이 필요한 이메일, 목요일 예정된 통화에 대한 준비 제안, 오후 일정이 빡빡하니 점심이나 헬스 일정을 조정하라는 제안, 그리고 저녁에 예약된 식사 자리를 지키라는 조언까지 담겨 있었습니다.

별다른 세부 지시 없이 "매일 아침 일정을 계획하도록 도와줘"라는 한 문장만으로 이 정도 결과가 나왔어요. 사용자가 피드백을 줄수록 점점 더 정교해진다고 설명합니다.

슬랙 메시지가 올라오면 자동으로 알림을 만들어주는 트리거도 설정했어요

시간 기반 루틴 외에 슬랙 메시지, 깃허브 이벤트, 팀즈 메시지 같은 실제 이벤트를 트리거로 쓰는 것도 가능합니다.

슬랙의 특정 채널에 새 메시지가 올라오면 알려달라고 요청하자, 그록 봇은 해당 채널을 찾아 트리거와 지시 내용을 스스로 구성했어요. 다만 작동하려면 그 슬랙 채널에 "/invite @cursor" 명령으로 봇을 초대하는 설정 단계가 필요했습니다.

초대를 마친 뒤 스폰서십 계약이 성사됐다는 테스트 메시지를 슬랙에 올리자, 몇 초 만에 그록 봇이 해당 내용을 요약해 알려줬어요.

비교가 인상적입니다. 같은 작업을 n8n으로 만들면 15분, 클로드 코드로 만들면 7분 정도 걸렸을 텐데, 이번에는 프롬프트 한 번, 2분 만에 끝났다고요.

에이전트들끼리 서로 대화하며 업무를 처리하고, 그 내용을 폰에서도 그대로 확인할 수 있어요

비서 역할인 클라우스에게 최근 유튜브 영상 관련 소식을 슬랙에서 확인해달라고 요청하면, 클라우스는 슬랙 미디어 담당 에이전트인 머니에게 직접 메시지를 보내 상황을 물어보고 답변을 받아 사용자에게 전달합니다.

두 에이전트가 주고받은 대화는 사용자가 볼 수 있게 남아 있어요. 어느 에이전트가 무엇을 물었고 어떻게 답했는지 그대로 확인 가능하죠.

이 모든 상태는 폰에서도 동일하게 이어집니다. 컴퓨터를 끄고 나가도 폰으로 클라우스와 계속 대화할 수 있고, 클라우스가 쓰고 있는 컴퓨터 화면(브라우저)까지 폰에서 직접 조작할 수 있어요.

딥워크에는 기존 도구를, 이동 중에는 그록 봇을 쓴다는 사용 기준을 제시했어요

책상에 앉아 집중해서 코드를 짜거나 소프트웨어를 만드는 작업은 여전히 클로드 코드나 코덱스로 한다고 해요. 이동 중이거나 우버 뒷좌석, 여행지, 식당처럼 폰만 있는 상황에서는 그록 봇을 쓴다고 기준을 밝혔습니다.

이 도구는 백엔드에서 그록 모델을 쓰기 때문에, 다른 모델을 선호하는 사람에게는 맞지 않을 수 있다고도 언급해요.

실제로 클라우스와 데브에게 대기자 명단 페이지를 만들어달라고 요청하는 시연도 보여줍니다. 처음 나온 결과물은 브랜드 가이드라인을 반영하지 못해 색상이 어긋나 있었어요.

그런데 클라우스는 왜 브랜드 가이드라인을 쓰지 않았는지 스스로 확인한 뒤, 깃허브 저장소에서 가이드라인을 찾아 데브에게 다시 전달했습니다. 이 대화 내용도 그대로 사용자에게 공개됐죠.

마지막으로 좋은 조언을 남겨요. 필요하지도 않은데 에이전트와 루틴을 무작정 늘리지 말고, 실제로 겪고 있는 병목이 무엇인지 먼저 판단하라고요.

핵심 인사이트

  • 에이전트별 전용 컴퓨터가 반복 업무 자동화의 핵심이에요: 각 에이전트가 독립된 브라우저·로그인 세션을 갖고 있어서, 사람이 하던 클릭·입력 작업을 그대로 녹화해 스킬로 재현할 수 있습니다. 이게 되면 로그인이 필요한 웹 작업(커뮤니티 관리, 리서치 등)도 자동화 대상이 되죠.
  • 이름·타이틀·설명만으로 에이전트 간 업무 위임이 자동 작동해요: 하나의 만능 에이전트보다, 역할이 좁고 설명이 명확한 여러 에이전트를 만드는 편이 낫다는 게 영상의 핵심 메시지입니다. 설명이 라우팅 기준이 되기 때문에, 역할을 세분화할수록 위임 정확도가 올라가요.
  • 트리거 자동화 설정 속도가 기존 노코드 도구보다 훨씬 빨라요: 슬랙 메시지 트리거를 프롬프트 한 번으로 2분 만에 만든 사례는, n8n(15분)이나 클로드 코드(7분) 대비 진입장벽이 크게 낮아졌다는 걸 보여줍니다. 자동화를 직접 설계하지 못하는 사람도 대화만으로 이벤트 기반 알림을 만들 수 있다는 뜻이죠.
  • 모든 도구를 무조건 도입하기보다 실제 병목부터 판단해야 해요: 네이트(Nate) 스스로도 딥워크는 기존 도구로, 이동 중 업무만 이 도구로 나눠 쓴다고 선을 그었습니다. 새 자동화 도구를 들일 때는 "이게 지금 내 업무의 어떤 병목을 없애주는가"를 먼저 따져야 시간 낭비를 피할 수 있어요.

오늘 당장 해볼 것

  1. 이동 중이나 대기 시간에 폰으로 처리하는 반복 업무(이메일 확인, 일정 조율, 커뮤니티·SNS 관리 등)를 한 번 나열해보세요. 그중 "로그인이 필요한 웹 작업"이 몇 개나 되는지 세어보시면, 이 목록이 자동화 우선순위가 됩니다.
  2. 현재 혼자 처리 중인 업무를 "비서", "미디어 대응", "아침 브리핑"처럼 역할 단위로 3개만 쪼개보고, 각 역할에 어떤 서비스(이메일, 캘린더, 메신저 등) 연결이 필요한지 적어보세요.
  3. 거래 중인 자동화 업체나 개발 담당자에게 "슬랙 메시지나 이메일 수신 같은 이벤트가 발생하면 자동으로 알림·요약해주는 루틴을 만들 수 있는지" 구체적으로 물어보고, 견적과 소요 시간을 비교해보세요.
