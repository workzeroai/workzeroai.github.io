GPT-6 Astra에 DeepSeek을 붙였다 (비용 100분의 1)

출처 · Jack Roberts이 글은 아래 영상 내용을 한국어로 요약·정리한 것입니다. 원문의 주장과 수치는 영상 제작자의 것입니다.원제 · I Combined GPT-6 Astra With DeepSeek... (100x Cheaper)

핵심
  • "프론티어 모델 vs 워크호스 모델" 이원화 전략이에요
  • "기존 것 유지·보완"과 "처음부터 새로 만들기"는 전혀 다른 난이도예요
  • 구독 한도에 도달했을 때의 대안이 생깁니다

한 줄 요약

Jack이 신규 오픈소스 모델 DeepSeek V4.1을 GPT-6 Astra와 실제로 엮어서(코드명 "Deep Astra") 프레젠테이션 디자인, 5만 행 데이터 분석, 대시보드 재설계까지 테스트했어요. 결론은 DeepSeek이 벤치마크에서 크게 도약했고, Astra보다 훨씬 저렴한 "워크호스" 모델로 쓸 수 있다는 겁니다.

전체 내용 정리

벤치마크에서 크게 도약했어요

DeepSeek의 신규 모델 V4.1은 오픈 웨이트이며 백만 토큰 컨텍스트를 지원하고 누구나 접근할 수 있습니다.

성적이 인상적이에요.

  • 오토메이션 벤치(멀티스텝 자동화 수행 능력) — 이전 버전 V4가 37.7점이었는데 V4.1은 54.8점으로 뛰어올라 Opus 5와 GPT-5.6 Sol에 견줄 만한 수준
  • 소프트웨어 엔지니어링 벤치마크 — 74.2%로 Opus 5를 앞지르고 GPT-5.6 Sol도 약 1% 차이로 근소하게 앞섬
  • 터미널 벤치 2.1 — 90.6%

멀티모달 지원도 되고, 웹 앱 작업과 비즈니스 워크플로우 처리 성능도 GPT-5.6 Sol보다 낫다고 평가됩니다.

두 모델을 연결하는 법

DeepSeek을 쓰는 방법은 크게 두 가지예요.

하나는 DeepSeek 하니스(DeepSeek판 Claude Code 같은 개념)를 무료 GitHub 저장소에서 받아 코딩·빌드에 바로 쓰는 방법입니다.

다른 하나가 이 영상의 핵심인데요. 이 저장소 내용을 복사해 OpenAI의 Codex 프레임워크에 붙여넣고 "챗GPT Codex 프레임워크 안에서 터미널로 DeepSeek을 열어 달라"고 요청하는 거예요. 이렇게 하면 Astra가 기존에 갖고 있던 파일과 도구 접근 권한을 그대로 활용해 DeepSeek에게 작업을 위임할 수 있게 됩니다.

DeepSeek은 로컬에도 호스팅할 수 있는 모델이라는 점도 특징이고요.

Jack은 DeepSeek 플랫폼 웹사이트에서 API 키를 직접 발급받아 쓰는 방식을 추천합니다. Open Router를 거칠 때는 종종 속도 제한에 걸렸는데, 직접 발급받은 키를 쓰자 그런 문제 없이 훨씬 매끄러웠다고 해요. 이미지·영상 생성 도구인 Higgsfield도 MCP CLI로 연결해 DeepSeek에게 이미지 생성 권한을 부여했습니다.

디자인 테스트: 프레젠테이션과 리브랜딩

첫 번째 테스트는 DeepSeek 단독으로 프레젠테이션을 만들게 한 것이었어요.

참고할 웹사이트 디자인을 보여 주며 그 느낌을 따라 만들어 달라고 요청했고, Astra의 개입 없이 DeepSeek 혼자 애니메이션이 들어간 제법 근사한 슬라이드를 완성했습니다. 다만 처음 프롬프트만으로는 완성도가 떨어져 서너 차례 수정 요청을 거쳐야 했어요.

두 번째는 Astra가 이미 만들어 둔 웹사이트를 DeepSeek에게 넘겨 "Bricks"라는 가상의 AI 인프라 회사용으로 텍스트와 로고를 바꿔 달라고 요청한 겁니다.

DeepSeek은 로고 디자인 자체를 새로 만들지는 못했어요. 하지만 기존 디자인 시스템과 톤을 그대로 유지하면서 텍스트·로고·이미지를 자연스럽게 바꿔냈습니다.

Jack은 같은 작업을 Astra로 했다면 비용이 훨씬 컸을 거라며, 처음부터 새로 디자인하는 데는 DeepSeek이 아직 최고 수준은 아니지만 기존 디자인 시스템을 유지·보완하는 작업에는 충분히 믿을 만하다고 평가해요.

데이터 분석이 가장 강했어요

DeepSeek이 가장 강점을 보인 영역은 데이터 분석이었습니다.

Jack은 DeepSeek과 Astra 양쪽 모두에게 5만 개가 넘는 행(그중 4만 5000건 이상은 결제 완료 주문)이 담긴 데이터를 주고 17개 질문에 답하도록 했어요.

결과는 두 모델 모두 100% 정확도였습니다.

매출이 어디서 얼마나 발생했는지 등을 정리한 리포트를 각각 만들어 비교했을 때, 디자인 완성도는 Astra가 앞섰지만 분석 내용 자체는 벤치마크에서 나타난 성능과 일치했어요.

비즈니스 대시보드 재설계

마지막 테스트로 Jack은 자신의 커뮤니티용 "에이전틱 운영체제"에 포함된 비즈니스 대시보드를 재구성해 달라고 요청했습니다. 계좌 현황, 지출·절감액, 인사이트 등을 보여 주는 Mercury 같은 형태로, 온보딩까지 포함해 만드는 데 약 8시간이 걸린 꽤 복잡한 제품이에요.

DeepSeek은 기존 타이포그래피를 그대로 유지하면서, 하나의 긴 스크롤 섹션이었던 화면을 여러 섹션으로 나눠 재구성했습니다. AI 지출 개요, 절감액, 개선 활동 인사이트, 모델별 사용량 상세, 워크스페이스·메모리 시스템·지식 그래프 현황, 시스템 정보로요.

이 작업에 든 비용은 약 9.5센트, 소요 시간은 7분 18초였어요. Jack은 이 결과에 크게 만족했다고 밝힙니다.

비용, 로컬 호스팅, 그리고 약점

입출력 토큰 기준 가격을 비교하면 이렇습니다.

| 모델 | 가격 | |---|---| | GPT-6 Astra | 60달러 | | GPT-5.6 Sol | 24달러 | | DeepSeek V4.1 | 약 0.75달러 (비피크 기준, 피크엔 약 2배) |

다만 단서가 붙어요. DeepSeek은 같은 작업에 Astra보다 더 많은 토큰을 쓰는 경향이 있어서, 토큰당 효율(지능/토큰)은 Astra가 더 높습니다.

로컬 호스팅도 가능한데, RTX 5090급 GPU와 그에 맞는 램을 갖춘 시스템 기준으로 약 1만 3000달러 이상이 들고 초당 약 5토큰 속도가 나온다고 추정돼요.

약점도 분명합니다. 처음부터 새로 디자인하는 작업, 난도 높은 코딩 작업(이런 건 여전히 Astra 6에 맡기는 게 낫습니다), 복잡한 PDF 처리, 전문 지식 질문, 그리고 특히 사실 확인 신뢰도요.

재밌는 건 Jack이 DeepSeek V4.1의 정확한 출시일을 DeepSeek 자신에게 직접 물어 확인했다는 점이에요(약 9월 10일경 출시). 이는 사실 확인용으로는 DeepSeek을 신뢰하지 않는다는 그의 원칙과도 맞닿아 있습니다.

결론적으로 Jack은 Astra를 프론티어급 고난도 사고 작업에, DeepSeek V4.1을 저렴하고 믿을 만한 "워크호스" 모델로 병행 사용하며, Astra가 특정 작업을 DeepSeek에게 위임하도록 하는 "Deep Astra" 워크플로우를 앞으로도 계속 쓸 계획이라고 밝혀요.

핵심 인사이트

  • "프론티어 모델 vs 워크호스 모델" 이원화 전략이에요: 가장 똑똑한 모델 하나로 모든 걸 처리하기보다, 난도 높은 판단은 프론티어 모델에 맡기고 반복적이거나 명확히 정의된 작업은 훨씬 저렴한 모델에 위임하는 구조가 비용과 품질 모두에서 이득이라는 걸 실측(9.5센트, 7분 18초)으로 보여 줍니다.
  • "기존 것 유지·보완"과 "처음부터 새로 만들기"는 전혀 다른 난이도예요: DeepSeek은 이미 있는 디자인 시스템을 그대로 따라가며 부분 수정하는 데는 강하지만, 백지에서 새로 설계하는 작업에는 아직 약합니다. 저렴한 모델을 도입할 때 "어떤 유형의 작업인가"를 구분하는 게 비용 절감의 핵심이에요.
  • 구독 한도에 도달했을 때의 대안이 생깁니다: 고가 모델의 사용량 한도에 자주 부딪히는 사람이라면, 특정 작업을 자동으로 저비용 모델에 위임하는 연결 구조를 만들어 두는 것만으로 실질적인 비용 절감과 처리량 확장이 가능해요.

오늘 당장 해볼 것

  1. 지금 쓰는 AI 자동화나 업무 중에서 "매번 똑같은 패턴으로 반복되는 작업"과 "매번 새로운 판단이 필요한 작업"을 구분해 목록으로 정리해 보세요. 전자가 저비용 모델로 넘길 수 있는 후보입니다.
  2. DeepSeek 플랫폼에서 API 키를 직접 발급받아 소액(20달러 정도)을 충전해 두고, 기존에 쓰던 라우팅 서비스 대비 속도와 안정성을 비교해 보세요.
  3. 반복적으로 손이 가는 디자인 수정 작업 하나를 골라, 기존 디자인 시스템을 그대로 유지한 채 저비용 모델에 맡겨 보고 결과물과 소요 비용·시간을 기록해 보세요.
