핵심
  • 저장소는 무료, 돈은 결과물에서 나와요

  • 절약 광고 수치는 그대로 믿으면 안 돼요

한 줄 요약

Nate Herk가 Claude용 GitHub 저장소 100개 넘게 직접 써 보고 골라낸 10개(+보너스)를 소개해요. 영상 편집, 구글 계정 연동, 스크래핑, 웹사이트, 앱, 결제, 테스트, SEO까지 각 저장소가 어떤 문제를 풀고 그걸로 어떻게 돈 받는 결과물을 만드는지 정리했어요.

전체 내용 정리

10만 개 중 대부분은 시간 낭비예요

지금 Claude를 위해 만들어진 GitHub 저장소는 10만 개가 넘어요. Nate는 솔직히 그중 대부분이 시간 낭비라고 말해요. 그래서 100개 넘는 저장소를 직접 써 보고, 없어서는 안 될 10개를 추렸다고 하죠.

그중 일부는 프로젝트를 10배 빠르게 끝내 주고, 매달 돈을 내던 도구 값을 아껴 주고, 작업 흐름의 일부를 아예 대신해 줘요. 영상은 각 저장소가 무엇이고 어떤 문제를 푸는지, 그리고 기업이 기꺼이 돈을 낼 결과물로 어떻게 연결하는지에 초점을 맞춰요.

영상 편집과 구글 연동, 스크래핑은 Hyperframes·Google Workspace CLI·Apify MCP가 맡아요

첫 번째는 HeyGen이 만든 Hyperframes예요. Claude에게 원하는 걸 자연어로 말하면 HTML과 애니메이션으로 영상을 구성하고, Hyperframes가 그걸 내 컴퓨터에서 실제 MP4로 렌더링해 줘요. 자막, 모션 그래픽, 타이틀 카드, 제품 홍보 영상까지 다 만들 수 있죠.

Nate는 이 위에 기능을 더해 유튜브 인트로, 인스타그램 릴스, 강의 영상, 광고를 만들어요. 원본 클립을 넣고 "자막이랑 타이틀 카드 넣어 줄래?" 또는 "인스타그램 릴스로 바꿔 줄래?"라고 하면 몇 분 뒤 완성 파일이 나온다고 해요. 비슷한 도구로 Remotion도 있지만, Nate는 Hyperframes로 훨씬 좋은 결과를 냈다고 해요. 광고가 아니라 직접 써 본 경험이라고 덧붙이고요.

오픈소스라 렌더링 비용이 없어서 완전히 무료예요. 영상을 올리는 거의 모든 기업은 편집 대행비를 낼 의사가 있거든요. 예를 들어 매달 자막 영상 20개가 필요한 헬스장에 월간 콘텐츠 패키지로 팔 수 있어요. 영상 편집 경험은 전혀 없어도 된다고 해요.

두 번째는 Nate가 가장 많이 쓰는 Google Workspace CLI예요. 구글 드라이브, 지메일, 캘린더, 문서, 스프레드시트, 프레젠테이션 등 구글 계정 안의 거의 모든 것과 Claude를 연동하고, 결과도 깔끔하게 정리해 줘요.

Claude에 내장된 Google 커넥터도 있지만, 그건 Claude 데스크톱 앱 안에서만 돌아가고 모든 걸 다루지도 못해요. 반면 이건 CLI(명령줄 도구)라서 Claude Code, Codex, 직접 만든 어떤 에이전트든 쓸 수 있어요. 40개가 넘는 스킬이 들어 있어서 Claude가 사용법을 이미 알고 있고요.

설정은 몇 분이면 끝나요. 로그인에 Google Cloud 프로젝트가 필요하긴 하지만 Claude가 단계별로 안내해 주고, 실제로 쓸 앱에만 접근 권한을 주면 돼요. 대부분의 소규모 기업은 구글 기반으로 돌아가니까 주간 보고서, 송장, 후속 이메일 같은 걸 빠르게 자동화해 줄 수 있죠.

세 번째는 Apify, 정확히는 Apify MCP 서버예요. Instagram이나 Reddit 같은 사이트는 접근을 막거나 JavaScript가 로드돼야 내용이 보여서, Claude는 기본적으로 빈 페이지만 받아요. Apify는 Instagram, TikTok, Amazon 등 수천 개의 기성 스크레이퍼(scraper, 웹 데이터 수집기)를 Claude에 연결해 줘요.

그래서 Nate는 이런 식으로 물어요. "Instagram에서 시카고의 특정 업종 매장을 찾아서 팔로워 수를 알려 주고, 영상을 내려받고, 바이오에 웹사이트가 없는 곳을 보여 줘." 그러면 몇 분 뒤 스프레드시트가 완성돼요.

커넥터는 오픈소스지만 스크레이퍼는 Apify 클라우드에서 돌아가서, 쓰는 스크레이퍼에 따라 몇 달러가 들 수 있어요. 무료 플랜은 월 5달러 크레딧을 주고, 일부 액터(actor, Apify의 개별 스크레이퍼)는 결과당 요금이 붙어요. Firecrawl 같은 오픈소스 스크래핑 저장소도 있지만, Apify가 정말 쓰기 쉽다고 해요.

Scrollcraft와 Humanizer는 사이트와 문구에서 AI 티를 걷어 내요

네 번째는 Nate가 직접 만든 Scrollcraft예요. 스크롤할 때 영화처럼 페이지 전체가 움직이고 여러 레이어가 겹치는 애플 스타일 사이트를 본 적 있을 거예요. 그런데 Claude에게 만들어 달라고 하면 보통 어색한 텍스트 페이드인이 들어간 평범한 페이지가 나오죠.

Scrollcraft는 Claude에게 실제 스크롤 엔진과 Nate가 여러 사이트를 만들며 쌓은 디자인 규칙을 줘요. 스크롤을 캡처해 위치를 확인하는 검사기도 들어 있어서, 사용자가 지적하기 전에 Claude가 오류를 먼저 고쳐요. Nate의 AI 자동화 커뮤니티 사이트, 개인 사이트, 이벤트 사이트가 모두 이 저장소를 써요.

모든 사이트가 화려한 스크롤일 필요는 없어요. 이 저장소는 깊이감, 레이어, 간격, 타이포그래피, 색 조합 같은 감각 요소도 이해하거든요. 웹사이트의 핵심은 좋은 인상을 주고 원하는 행동으로 이끄는 거예요. AI 시대에 기본 랜딩 페이지는 흔한 상품이 됐지만, 온라인에서 물건을 파는 브랜드는 여전히 커스텀 스크롤 경험에 디자이너 비용을 크게 쓴다고 해요.

다섯 번째는 거의 우연히 찾았는데 이후 모든 제품에 쓰고 있다는 Humanizer예요. Claude가 쓴 글에서 AI 특유의 딱딱함을 걷어 내 줘요. 위키피디아 편집자들이 AI 생성 글을 잡아낼 때 쓰는 가이드를 바탕으로 만들어졌죠.

그래서 '이것이 아니라 저것' 같은 표현, 뜸 들이는 도입부, 뭐든 세 개로 나열하는 버릇, 과장된 홍보 문구처럼 보자마자 AI 글로 느껴지는 징후를 다 알고 있어요. 웹사이트 문구나 콜드 메일을 붙여 넣고 사람처럼 바꿔 달라고 하면, 의미는 유지하면서 읽는 사람이 바로 스크롤을 내리거나 신뢰를 잃게 만드는 요소를 지워 줘요. 사람이 쓴 것처럼 읽히는 글이 훨씬 설득력 있으니까요.

여기까지 다섯 개는 주로 클라이언트를 데려오는 데 쓰는 도구예요. 나머지는 청소 업체처럼 온라인 예약과 보증금 결제가 필요한 실제 서비스를 만들어 달라는 의뢰를 받았을 때 더 쓸모가 있어요.

실제 서비스를 만들 땐 Agent Skills·Expo·Supabase·Stripe 스킬을 써요

작업 한두 시간쯤 지나면 Claude가 갑자기 앞 내용을 다 잊은 것처럼 답할 때가 있죠. 긴 세션은 압축되거나 맥락이 흐려지면서 초반 세부 사항이 요약돼 사라지기 때문이에요. 여섯 번째 저장소가 이 문제를 풀어요. Addy Osmani가 만든 Agent Skills인데, Addy는 Google에서 14년을 일했고 지금은 Anthropic에서 Claude Code를 다루고 있다고 해요.

이 도구는 채팅 속 계획을 파일로 빼 줘요. /spec으로 실제 사양서를 함께 쓰고, /plan으로 작업을 작은 단위로 쪼개고, /build로 단계마다 확인하면서 하나씩 진행하죠. 세션이 복잡해지면 새 세션을 열어도 하던 곳부터 바로 이어 갈 수 있어요.

사양서 단계에서는 이중 예약, 환불, 시간대가 다른 고객처럼 미처 생각 못 한 부분까지 물어봐요. 이런 예외는 반드시 사양과 빌드에 들어가야 하거든요. 빌드 전에 사양서를 클라이언트에게 보내면 무엇을 받게 될지 정확히 알 수 있어서, 끝까지 같은 목표를 보고 갈 수 있어요.

5월 영상에서 다룬 Superpowers를 쓰고 있다면 그것도 여전히 훌륭하지만, 초보자에겐 Addy의 방식이 따라 하기 더 쉽다고 해요. 보너스로 Matt Pocock의 스킬도 소개해요. 개발자가 아니어도 개발자처럼 만들고 싶다면 아주 좋은 저장소라고 해요.

일곱 번째는 모바일 앱용 Expo 공식 스킬이에요. Windows를 쓰더라도 오후 한나절이면 아이디어에서 실제 아이폰에서 돌아가는 앱까지 갈 수 있다고 해요. 앱을 AI가 만든 티가 나게 하는 요소 20가지와 앱스토어 등록을 위한 최신 규칙이 들어 있어요.

팁도 하나 줘요. 스킬이 자동으로 로드되지 않을 때가 있으니 Claude에게 스킬 이름으로 직접 호출하라고 하세요. TestFlight나 앱스토어에 올리려면 연 99달러짜리 Apple 개발자 계정이 필요해요. 대부분의 매장은 이미 Square 같은 결제 시스템을 쓰고 있으니, 기존 소프트웨어가 못 푸는 워크플로를 제안해 보라고 해요.

여덟 번째는 백엔드예요. 로그인, 데이터베이스, 결제가 필요한 앱이라면(거의 모든 앱이 그렇죠) Supabase와 Stripe 공식 스킬을 쓰면 Claude가 각 회사의 보안 규칙을 잘 알게 돼요. 사용자가 자기 데이터만 보게 하거나, 결제가 정말 Stripe에서 왔는지 확인하는 식이죠.

Stripe는 전체 플러그인 대신 'Stripe best practices' 스킬 하나만 설치하라고 권해요. 전체 플러그인을 깔면 모든 결정을 Stripe 쪽으로 처리하려 들 수 있거든요. Supabase 커넥터는 읽기 전용으로 두고, 출시 전에 테스트 사용자로 로그인해 다른 사람 데이터가 안 보이는지 확인하라고 해요. 백엔드와 결제는 헷갈리기 쉽고 보안 걱정이 큰 영역이라 이 스킬들을 쓰라는 거죠.

넘기기 전엔 Playwright CLI·Claude Security로 검증하고, Open SEO로 찾아오게 해요

아홉 번째는 클라이언트에게 넘기거나 공개하기 전에 꼭 돌려야 할 단계예요. Claude는 기꺼이 "네, 잘 작동해요"라고 말하지만, 실제로 버튼을 눌러 보지 않았을 수 있거든요.

Microsoft의 Playwright CLI는 실제 브라우저를 열고 고객처럼 앱을 클릭하면서 테스트를 쓰고, 그걸 계속 다시 돌려 모든 걸 검증해요. MCP가 아닌 명령줄 도구라서 페이지 전체를 Claude의 컨텍스트에 쏟아붓지 않아요. 그래서 토큰도 훨씬 덜 쓰고 속도도 훨씬 빨라요.

Anthropic의 보안 플러그인 Claude Security도 함께 써요. 에이전트 팀을 코드에 투입해 허점을 찾게 하고, 서로 다른 에이전트가 상대의 발견이 틀렸음을 증명하려 들죠. 남은 문제는 쉬운 영어 보고서로 받고, Claude가 패치를 쓰고 적용까지 해 줘요. 클라이언트는 이런 테스트 자체엔 관심이 없지만, 예약 양식이 잘 돌아가고 고객 데이터가 새지 않는 것은 매우 중요하게 여겨요. 그래서 모든 프로젝트에 이 과정을 넣으라고 해요.

마지막 열 번째는 Open SEO예요. 사이트나 앱을 냈으면 사람들이 찾아와야 하니까요. Claude를 실제 키워드 데이터, 순위, 백링크에 연결해서, 뻔한 조언 대신 지금 어느 페이지가 어떤 키워드에 있는지 정확히 알려 줘요.

에이전시들은 이런 감사(audit)를 월간 SEO 계약을 따내는 데 써요. 다만 무료 체험 크레딧은 적고, 직접 호스팅하지 않으면 데이터가 기본적으로 서버에 저장된다는 점은 알아 두라고 해요.

토큰 절약 저장소는 광고만큼 못 아꼈고, 시작은 하나부터 하래요

Caveman, RTK, Ponytail 같은 토큰 절약용 저장소가 궁금한 사람도 있을 텐데요. JetBrains가 이 셋을 실제 코딩 작업으로 테스트했다고 해요. Caveman은 65% 절감을 내세웠지만 실제로는 출력 토큰을 약 8.5%만 줄였어요. RTK는 사실상 효과가 없었고, 낮은 작업 강도에선 오히려 비용이 더 들었죠. 비용을 줄인 건 Ponytail뿐인데, 광고의 절반 수준인 작업당 약 10%였어요. 게다가 Windows에서는 메시지마다 몇 초씩 지연되는 버그가 있다고 해요.

토큰이 어디로 새는지 알고 싶다면 Codeburn으로 지출을 확인하고, 쓰지도 않는데 메시지마다 로드되는 MCP 서버 같은 낭비를 찾아보라고 권해요. 5월에 추천했던 Claude Mem과 Context Mode는 일단 보류하라고 해요. Claude Mem은 기본 설정으로 사용 데이터를 전송하고, Context Mode에는 사용량을 급격히 소모하는 버그가 있대요.

이 분야가 처음이라면 오늘 전부 설치하지 말라고 Nate는 당부해요. 부담스럽기도 하고, 문제가 생겼을 때 어느 저장소 탓인지 알기 어렵거든요. 지금 가장 겪는 문제를 풀어 줄 하나만 고르고, 확신이 없으면 Google Workspace CLI, Apify, Scrollcraft 중에서 시작하라고 해요. Humanizer도 아주 간단해서 같이 써 보기 좋고요.

구체적인 첫 시도도 제안해요. 웹사이트가 없는 업체 목록을 뽑고, 샘플 페이지를 하나 만들고, 문구를 다듬어서 링크를 보내 보는 거예요.

GitHub 저장소를 보고 돈을 낼 사람은 없어요. 무료이고 누구나 설치할 수 있으니까요.

Nate가 강조하는 건 팔아야 할 게 저장소가 아니라 그걸로 상대의 문제를 해결한 결과물이라는 점이에요.

핵심 인사이트

  • 저장소는 무료, 돈은 결과물에서 나와요: 누구나 설치할 수 있는 도구 자체엔 아무도 돈을 안 내요. 헬스장 월 20개 자막 영상, 웹사이트 없는 업체용 샘플 페이지처럼 '해결된 문제'로 포장해야 팔려요.
  • Claude의 "잘 돼요"는 검증이 아니에요: Playwright CLI로 실제 클릭 테스트를, Claude Security로 보안 점검을 돌려야 해요. 클라이언트가 신경 쓰는 건 예약 양식이 돌아가고 데이터가 새지 않는 것이거든요.
  • 절약 광고 수치는 그대로 믿으면 안 돼요: 65% 절감을 내세운 도구가 실측 8.5%에 그쳤어요. 토큰을 아끼려면 Codeburn으로 실제 낭비부터 찾는 게 먼저예요.

오늘 당장 해볼 것

  1. Google Workspace CLI를 설치해 주간 보고서나 후속 이메일 하나를 자동화해 보세요. Claude가 Google Cloud 프로젝트 설정을 단계별로 안내해 주고, 대부분의 소규모 사업이 구글 위에서 돌아가서 효과를 바로 체감할 수 있어요.
  2. Apify MCP로 '웹사이트 없는 지역 업체' 목록을 뽑아 보는 것도 좋아요. 무료 플랜의 월 5달러 크레딧으로 시작할 수 있고, Scrollcraft로 샘플 페이지를 만들어 보내면 그대로 영업 리스트가 돼요.
  3. 납품 직전 단계에 Playwright CLI 테스트를 끼워 넣어 보세요. "잘 작동한다"는 Claude의 말 대신 실제 브라우저 클릭으로 확인하면, 예약·결제 오류로 클라이언트 신뢰를 잃을 일이 줄어들어요.
