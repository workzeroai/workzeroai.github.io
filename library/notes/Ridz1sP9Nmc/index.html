프롬프트 하나 쳤을 뿐인데 30분 만에 데스크톱 앱이 완성됩니다 (feat. 마누스 AI)

핵심

  • 완료 메시지와 실제 동작은 따로 확인해야 해요

한 줄 요약

조쉬가 마누스의 새 기능 '마이 컴퓨터'에 프롬프트를 하나씩 넣어서 맥용 데스크톱 앱 세 개(실시간 통역, 회의록 녹음·요약, 카카오톡 자동 전송)를 직접 만들어 본 시연이에요. 첫 앱은 30분 정도 기다리니 완성됐고, 카카오톡 앱은 한 번 실패한 뒤 수정을 거쳐서 돌아갔어요.

전체 내용 정리

마이 컴퓨터는 AI가 내 컴퓨터 안으로 들어와 일하는 기능이에요

마누스를 웹사이트 크롤링이나 프레젠테이션 생성에 쓰는 분이 많은데요. 최근 마누스에 '마이 컴퓨터'라는 기능이 나왔어요. 조쉬는 이걸 컴퓨터 안의 파일에 직접 접근해서 여러 가지를 통제하는 기능이라고 설명합니다. 오픈 클로나 클로드가 하는 일과 비슷하고, 특히 클로드 코워크와 꽤 닮았다고 봐요.

그럼 굳이 마누스를 쓸 이유가 있을까요? 조쉬는 마이 컴퓨터가 생각보다 꽤 강력하다는 걸 사례로 보여 주겠다며 데스크톱 앱 세 개를 만들어요. 말하면 실시간으로 영어 번역을 띄워 주는 앱, 회의 녹음을 무료로 해 주는 앱, 카카오톡 메시지를 자동으로 보내 주는 앱이에요.

준비는 간단합니다. 마누스 홈페이지에서 '데스크톱 앱 개발'을 누르면 다운로드 창이 뜨고, 거기서 데스크톱 앱을 받아 설치하면 돼요. 조쉬는 맥을 쓰고 있어서 앱을 옮겨 설치하는 화면이 나왔는데, 윈도우에서는 이 화면이 나오지 않는다고 해요.

앱을 열면 슬라이드 제작 같은 기능도 이미 들어 있어요. 다만 조쉬는 슬라이드나 웹사이트 구축은 이미 다른 방식으로 최적화해 두었기 때문에 오늘은 데스크톱 앱 개발에 집중한다고 밝힙니다. 데스크톱 앱 개발을 누르면 폴더를 고르는 창이 나오고, '로컬 폴더 추가'로 미리 만들어 둔 테스트 폴더를 연 뒤 파일 변경을 허용하면 준비가 끝나요.

이 상태에서는 클로드 코드나 클로드 코워크로 하던 컴퓨터 작업을 대부분 할 수 있어요. 다운로드 폴더 정리, 파일 이름이나 속성 바꾸기 같은 일이죠. 그런데 조쉬가 발견한 마누스의 큰 장점은 따로 있었어요. 데스크톱 앱을 아주 쉽게 만들어서 일상을 자동화할 수 있다는 점이에요.

프롬프트 하나로 실시간 회의 통역 앱이 완성됐어요

첫 프롬프트는 스위프트 언어로 실시간 회의 통역 앱을 개발해 달라는 요청이었어요. 여기에 "터미널과 폴더에만 접근할 수 있다는 점을 고려해서 터미널을 통해서 애플리케이션 개발 디버깅 패키징 작업 전체를 완료해 주세요"라는 문장을 덧붙였어요.

조쉬는 이 뒷부분을 핵심으로 꼽아요. 터미널에서 개발과 디버깅, 패키징까지 다 끝내서 완결된 앱을 달라고 하면 중간 과정을 싹 없앤 프롬프트가 되거든요. 사람의 의도는 통역 앱을 만들어 달라는 것 하나이고, 나머지는 마누스가 맡는 구조예요.

명령을 보내자 마누스는 컴퓨터를 초기화하고 생각부터 시작했어요. 계획을 꽤 타이트하게 세운 뒤 개발 환경 확인, 프로젝트 설계, 스위프트 패키지 매니저, 핵심 기능 구현, 빌드와 디버깅까지 단계별로 체크해 나갑니다. 조쉬는 스위프트 개발 환경인 X코드를 미리 깔아 둬서 이게 가능했다며, 맥용 앱을 만들고 싶다면 X코드를 따로 설치해 두라고 권해요.

30분 정도 기다리니 개발 완료 메시지와 함께 앱 실행 방법이 나왔어요. 안내된 명령어를 복사해 터미널에 붙여 넣자 프로그램이 곧바로 떴습니다. 맥용 앱이라서 디자인을 따로 신경 쓰지 않았는데도 화면이 잘 나왔다고 해요.

그런데 말을 걸어 보니 "오픈 AI의 API 키를 설정해 주세요"라는 안내가 나왔어요. 조쉬의 반응은 "역시 공짜가 없죠"였습니다. 오픈 AI 플랫폼에서 새 시크릿 키를 만들어 붙여 넣고 저장했어요. 이 키는 녹화용으로만 만들고 바로 폐기할 거라고 거듭 강조해요.

다시 녹음을 시작하자 한국어로 한 말이 실시간으로 번역돼 나왔어요. 일본어로 바꿔도 잘 나왔고, 중국어는 결과가 꽤 간결하게 나왔다고 해요. 화면에 '인식 오류' 표시가 뜨긴 했지만 조쉬가 보기엔 인식 자체는 잘 되고 있었어요. 처음 한 번 맡긴 것치고는 상당히 놀라운 결과물이라는 게 조쉬의 평가예요.

회의록 앱은 녹음을 바로 해 주고, 요약은 무료 API 키로 붙였어요

두 번째도 스위프트로 실시간 회의록 STT(음성을 글자로 받아 적는 기능) 앱을 만들어 달라고 했어요. 회의록은 현장에서 많이 쓰이고, 이를 요약해 주는 앱도 국내에 이미 유명한 게 몇 있죠. 조쉬는 이번엔 "음성 녹음이 좋은 품질로 녹음되어야 하며 실시간으로 음성을 잘 기록할 수 있는 형태로 제작을 해 주세요"라는 조건을 더 넣고, 뒤에는 첫 앱과 같은 터미널 문장을 붙였습니다.

완성된 앱으로 녹음해 보니 말하는 내용이 실시간으로 기록됐어요. 조쉬는 앱을 사거나 구독하지 않아도 바로 이렇게 된다는 점을 무척 재밌어해요. 그리고 여기서 끝내지 않고 회의록 요약 기능까지 붙였어요.

요약에는 API가 필요해서 구글 AI 스튜디오에서 키를 받았어요. 새 프로젝트를 만들어 API 키를 복사한 뒤, 마누스에게 요약 기능은 재미나이 API를 활용하라며 키를 넘겼죠. 이 키도 녹화가 끝나는 즉시 폐기한다고 하면서, 자신은 보안 이슈를 항상 강조한다는 말을 덧붙여요.

마누스는 "수정 완료 AI 요약 기능 정상화"라는 메시지와 함께 다시 빌드한 앱을 내놓았어요. 앱을 다시 켜고 회의록 요약하기를 누르자 "AI 요약 결과"라는 제목 아래 확인 내용, 결정 사항, 향후 계획 같은 항목으로 정리가 됐습니다.

조쉬가 보기에 받아 적기는 애플의 라이브러리를 활용해 앱 안에서 처리하는 것 같고, AI 요약만 무료 API 키를 붙여 해결한 구조예요. 간단한 녹음 정도라면 녹음 앱을 따로 살 필요 없이 이렇게 띄워서 쓰면 되지 않겠느냐는 게 조쉬의 제안이에요.

카카오톡 자동 전송 앱은 한 번 실패한 뒤 고쳐서 돌아갔어요

세 번째 프롬프트는 맥의 스크립트 기능을 써서 카카오톡에 자동으로 메시지를 보내는 앱을 만들어 달라는 내용이었어요. 여기에 "현재 대화창을 그대로 가져와서 그곳에 보낼 수 있는 맥용 스위프트 앱으로 만들어 주시고 완료되면 보고하세요"라는 문장을 붙였어요.

마누스는 이번에도 구현 방법부터 고민했어요. 조쉬는 요즘 바이브 코딩 서비스들이 생각을 많이 하고 계획을 짠 다음에 작업에 들어가는 게 유행인 것 같다고 말해요. 마누스는 맥OS 네이티브 앱으로 만들겠다고 밝히고 작업을 시작했어요.

결과물은 '카카오톡 자동 메시지 전송기'라는 앱이었어요. 불러오기를 누르면 대화창 목록을 가져오는 것처럼 보였고, 조쉬는 카카오톡의 나에게 보내기 창을 열어 둔 채 테스트했어요. 테스트 메시지를 쓰고 보내기를 누르자 "1회 전송 완료"라는 표시는 떴습니다.

그런데 정작 카카오톡 창에는 메시지가 들어오지 않았어요.

조쉬는 열려 있는 창에 메시지가 안 간다고 마누스에게 그대로 알렸어요. 마누스는 앱 없이 직접 자동 전송 테스트 메시지를 보내 보며 원인을 찾았고, 문제가 있다고 보고 재설계에 들어갔어요. 조쉬는 이렇게 약간 어려운 프로그램은 조금 더 보완이 필요해 보인다고 솔직하게 말해요.

잠시 뒤 "재빌드 완료"와 함께 근본 원인을 고쳤다는 보고가 왔어요. 이번에는 현재 활성 창으로 바로 보내지 않고 입력창에 메시지를 넣는 방식으로 "안녕하세요"를 보내 봤는데, 제대로 들어갔어요. 반복 횟수를 지정하는 기능도 잘 작동했습니다.

조쉬는 메시지 자동화로 어려움을 겪는 분이 생각보다 많다고 봐요. 자주 쓰는 메시지를 템플릿으로 저장해 두고 카카오톡을 자동화하면, CS나 문자 응대용 도구의 초안을 이런 식으로 만들어 볼 수 있다는 거예요.

조쉬는 웹사이트를 만드는 시대는 거의 끝났다고 봐요

마무리에서 조쉬는 마이 컴퓨터의 가장 큰 강점을 이렇게 정리해요. 웹사이트에 머물던 AI가 컴퓨터 안으로 들어오면서 자동화 시나리오를 빠르게 시도해 볼 수 있게 됐다는 점이에요. 다음에는 마누스를 24시간 원격 AI처럼 돌려 보는 테스트도 해 볼 계획이라고 해요.

조쉬는 바이브 코딩 도구로 웹사이트를 만드는 시대는 거의 끝난 것 같다고 말해요. 대신 "나에게 맞는 자동화된 유틸리티 앱을 스스로 만들어 보고 빠르게 테스트해 볼 수 있다"는 것 자체가 큰 변화라고 봅니다. 조쉬가 보는 다음 무대는 내 업무에 맞춘 작은 앱이에요.

핵심 인사이트

  • 프롬프트 끝 한 문장이 완성도를 정해요: 조쉬는 매번 터미널로 개발·디버깅·패키징까지 끝내 달라는 문장을 붙였어요. 중간 과정을 사람이 챙기지 않아도 실행되는 앱이 돌아온 데는 이 문장의 역할이 컸다는 게 조쉬의 설명이에요.
  • 앱은 만들어도 AI 기능에는 API 키가 따로 필요해요: 통역 앱은 오픈 AI 키, 요약 기능은 구글 AI 스튜디오 키를 붙여야 했어요. 조쉬가 키를 녹화 직후 폐기한다고 거듭 말한 것처럼, 키 관리까지 챙겨야 해요.
  • 완료 메시지와 실제 동작은 따로 확인해야 해요: 카카오톡 앱은 "1회 전송 완료"라고 떴지만 메시지는 가지 않았어요. 오류를 그대로 알려 주자 마누스가 원인을 고쳐 다시 빌드했죠. 그래서 직접 눌러 보고 결과를 되돌려 주는 과정이 꼭 필요해요.
  • 사서 쓰던 유틸리티를 직접 만들 수 있어요: 회의 녹음처럼 간단한 용도라면 따로 구매하지 않고 내가 만든 앱으로 충분하다는 게 조쉬의 관점이에요.

오늘 당장 해볼 것

  1. 마누스 데스크톱 앱을 설치하고 '데스크톱 앱 개발'에서 빈 테스트 폴더 하나만 연결해 보세요. 조쉬처럼 테스트용 폴더로 시작하면 중요한 파일을 건드릴 걱정 없이 실험할 수 있어요.
  2. 맥이라면 X코드를 먼저 설치한 뒤, 만들고 싶은 앱 요청에 터미널로 개발·디버깅·패키징까지 끝내 달라는 문장을 붙여 보세요. 끝 문장 하나로 바로 실행되는 앱이 돌아오는지 직접 비교해 볼 수 있어요.
  3. 회의 녹음 앱을 만들었다면 구글 AI 스튜디오에서 API 키를 하나 만들어 요약 기능까지 붙여 보세요. 녹음은 앱 안에서, 요약은 무료 키로 처리하는 영상 속 구조를 그대로 따라 할 수 있어요. 키는 테스트가 끝나면 폐기하세요.
