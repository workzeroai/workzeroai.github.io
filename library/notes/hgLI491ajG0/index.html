AI 도구 100개 넘게 써 보고 남긴 7개

핵심
  • 에이전트 하나가 여러 구독을 대신해요

  • 모든 자동화에 AI가 필요하진 않아요

한 줄 요약

AI 도구를 100개 넘게 써 본 Nate Herk가 매일 사업에 실제로 쓰는 7가지를 골랐어요. Claude Code·Codex, OpenRouter, Hostinger VPS, Grockbot, Glido, Kie.ai, trigger.dev를 어디에 어떻게 쓰는지까지 알려 줍니다.

전체 내용 정리

100개 넘게 써 보고 남긴 7개, 1위는 Claude Code와 Codex예요

Nate는 사업용으로 AI 도구를 100개 넘게 테스트해 보고 한 가지를 알아챘다고 해요. 대부분은 소음이거나, 꽤 기본적인 문제에 화려한 해법을 씌운 것이었다는 거죠. 새 도구가 계속 쏟아지는데도 매일 사업을 돌리는 방식을 실제로 바꾼 건 7개뿐이었다고 합니다.

몇 개는 단순하거나 지루하게 들릴 수 있다고 Nate도 인정해요. 그런데 처음 쓰기 시작할 때 예상한 것보다 사업에 훨씬 큰 영향을 줬다고 말합니다. 영상은 이 7개가 무엇인지, Nate가 어떻게 쓰는지, 왜 써 보라고 하는지를 차례로 짚어요.

첫 번째는 사실 두 개예요. Claude Code와 Codex는 내 컴퓨터에서 바로 돌아가는 AI 에이전트라서 로컬 파일을 읽고 코드를 쓰고 뭔가를 만들어 줘요. 말로 시키기만 하면 됩니다. Nate는 이 목록에서 딱 하나만 써야 한다면 둘 중 하나를 고르겠다고 할 만큼 사업에서 가장 큰 지렛대로 꼽아요.

슬라이드 덱, 스프레드시트, Google Docs를 만들고 브레인스토밍 상대나 조언자 역할도 맡겨요. Nate의 세컨드 브레인(second brain, 지식을 모아 두는 개인 저장소)도 여기 있어요. 모든 프로젝트, 스킬, 지식, 회의 녹취록이 다 들어가 있고, 매일 하는 업무의 약 90%를 이걸로 돌린다고 해요.

덕분에 돈을 내던 다른 도구도 많이 정리했어요. 예전엔 슬라이드용으로 Gamma, 콘텐츠용으로 Poppy를 결제했는데, 지금은 작은 맞춤 앱을 직접 만들어 써요. 자기만의 Loom도 만들었다고 해요. 원하는 도구를 설명만 하면 만들어지니 다른 회사 도구를 빌려 쓸 필요가 줄어든다는 거죠.

다만 Nate는 수십만 명이 쓰는 소프트웨어를 만드는 게 쉽다는 얘기는 아니라고 선을 그어요. 혼자 쓰거나 작은 팀이 쓰는 정도라면 위험이 크지 않다는 거예요. 시작점으로는 매달 돈을 내면서 기능 하나만 쓰는 도구를 직접 만들어 보거나, Claude Code에 SOP(표준 업무 절차서)와 고객 문서를 연결해 팀원이 나 대신 거기에 질문하게 하는 방법을 권해요.

둘 중 뭘 쓰냐는 질문에는 둘 다라고 답해요. 둘 다 결제하고 매주 둘 다 쓴다고 합니다. 어느 때는 한쪽 모델이 앞서고 어느 때는 한쪽 사용량이 더 오래 버텨서 자주 오간다고 해요. 대체로 Codex는 컴퓨터 사용(computer use)과 브라우저 사용에 강하고 Claude Code는 브레인스토밍할 때 더 좋은 생각 파트너라고 Nate는 봐요. 지금은 사용량도 더 오래 간다고 하는데, 두 달 뒤엔 달라질 수 있다고 덧붙여요.

그래서 어느 쪽이 최고냐가 아니라, 지금 하는 작업에 어느 쪽이 맞느냐의 문제라고 해요. Nate가 신경 쓰는 건 파일·폴더·프로젝트로 이뤄진 자기 AIOS(AI 운영체제)를 두 도구 사이에서 번거로움 없이 오갈 수 있게 짜 두는 쪽이에요.

OpenRouter 계정 하나로 500개 넘는 모델을 써요

두 번째는 OpenRouter예요. 계정 하나로 80곳 넘는 제공사의 AI 모델 500개 이상에 접근할 수 있어요. OpenAI, Anthropic, Google 같은 곳마다 키, 결제 정보, 비밀번호를 따로 관리할 필요가 없어지죠.

Nate의 회사가 지금 실제로 돌리는 자동화는 자기 사업용이든 고객사에 넣어 준 것이든 거의 다 OpenRouter를 모델 공급원으로 써요. 이유는 폴백(fallback, 대체 경로) 설정이에요. 한 모델이 다운되거나 오류를 내면 다음 모델로 넘어가서 자동화 전체가 멈추지 않아요. 자동화마다 API 키를 따로 만들 수 있어서 어느 자동화에 돈이 얼마나 드는지도 분석 화면에서 바로 보여요.

예를 들면 싸고 빠른 모델이 들어오는 리드를 분류하고 더 똑똑한 모델이 실제 답장을 쓰거나 추론을 맡게 할 수 있어요. 이 모든 게 한 대시보드, 한 제공사, 카드 한 장으로 돌아가요. 모델을 바꾸는 것도 사실상 한 줄만 고치면 된다고 합니다. 아주 단순한 도구라서 좋아한다는 게 Nate의 설명이에요.

Hostinger VPS는 24시간 켜져 있는 클라우드 컴퓨터예요

세 번째는 Hostinger VPS예요. 이 구간은 Hostinger 협찬이라고 밝히는데, Nate는 협찬이 아니어도 목록에 넣었을 거라고 해요. 실제로 오래 써 왔다는 거죠. VPS(가상 사설 서버)는 노트북이나 데스크톱을 꺼도 계속 켜져서 내 작업을 돌려 주는 클라우드 속 컴퓨터예요.

목록에서 가장 지루하게 들리지만 Nate의 작업이 많이 사는 곳이라고 해요. n8n을 돌리는 서버가 있고, Hermes 에이전트와 OpenClaw 에이전트, 나중에 직접 호스팅하고 싶은 다른 오픈소스 에이전트나 오픈소스 모델도 올려요. Hermes 에이전트 중엔 주식을 거래하는 것도, Instagram 릴스와 캐러셀을 24시간 만드는 것도 있어요. 다른 Claude Code 설정을 시험하는 용도로도 써요.

Hostinger를 고른 이유는 버튼 한 번으로 서버를 빠르게 띄울 수 있어서예요. Nate는 기술이나 DevOps(개발·운영) 배경이 없어서 스케일링, 컴퓨팅 자원, 명령어 같은 걸 신경 쓰고 싶지 않았다고 해요. n8n, Hermes, OpenClaw처럼 뜨는 도구를 원클릭 템플릿으로 올릴 수 있고, 자는 동안 뭔가 꺼져서 원인도 모르는 상황을 걱정하지 않아도 된다고 말해요.

Grockbot은 주머니 속에서 도는 작은 봇들이에요

네 번째는 Grockbot이에요. Nate가 정말 많이 쓴다고 해요. 일을 대신 해 주는 봇을 만들 수 있고, 봇들이 브라우저·파일 시스템·터미널이 달린 클라우드 컴퓨터를 함께 써요. 그래서 실제 컴퓨터에서 내가 할 수 있는 일은 거의 다 할 수 있죠.

Nate가 좋아하는 건 자동화를 세팅하는 속도예요. 이미 쓰는 앱들과 연결되는 커넥터가 들어 있고, 휴대폰 앱과도 거의 자동으로 동기화돼요. 일정이나 웹훅(webhook, 특정 이벤트가 생기면 신호를 보내는 장치)으로 돌아가는 루틴을 쉽게 만들어 두면, 주머니 속에서 계속 백그라운드로 돌아가요.

예시도 들어요. Plus 커뮤니티에서 Q&A 통화가 끝날 때마다 Grockbot이 녹취록을 가져와 커뮤니티에 올리고 회원들이 나중에 찾을 수 있게 클래스룸에도 넣어요. 유튜브 영상이 올라갈 때마다 두 커뮤니티에 글을 올리는 봇도 있고, AI 소식을 계속 알려 주는 봇도 있어요. 깜빡하면 나중에 따라잡아야 하는 반복 작업을 맡겨서, 완벽하게 꾸준하지 않아도 되고 실수할 여지도 줄었다고 해요.

Nate는 각각 아주 구체적인 일을 맡은 Grockbot 캐릭터를 여러 개 만들어 뒀어요. 그의 표현으로는 주머니 속에 OpenClaw를 여러 개 넣고 다니는 것과 비슷한데 기술 세팅은 훨씬 적은 것이에요. OpenClaw는 서버, 연결, 호스팅을 직접 알아내야 하지만, Grockbot은 원하는 걸 설명하면 되고 노트북이나 휴대폰에 설치하는 앱일 뿐이라고 해요.

Glido는 말로 받아쓰고, 말로 일을 시키는 앱이에요

다섯 번째는 Glido예요. Nate는 자신이 Glido의 파트너라고 먼저 밝히고, 그만큼 실제로 쓰고 비전을 믿는다는 뜻이라고 말해요. 키를 누른 채 말하면 지금 쓰는 앱에 글자가 입력되는 음성 받아쓰기 앱이에요. Nate는 프롬프트, 메시지, 이메일을 이제 거의 타이핑하지 않고 마이크에 대고 말한다고 해요. 설정을 세세하게 바꿀 수 있고, 시장에서 가장 빠르며 완전히 비공개라고 소개합니다.

목록에 넣은 진짜 이유는 커맨드 모드예요. 받아쓰기만이 아니라 행동도 해 줘요. 웹 검색, 유튜브 영상 요약, 딥 리서치, 파일과 앱 찾아 열기를 시킬 수 있고, 지금까지 Glido에 말한 내용을 다시 찾아볼 수도 있어요. 이 기록은 모두 로컬에 저장돼요.

커맨드 모드에는 맞춤 도구도 붙일 수 있어요. 그 위에 MCP 서버를, 그러니까 사실상 플러그인을 만들어 붙여서 Claude Code나 Codex에 작업 스레드를 띄우거나 Notion, 할 일 앱과 동기화할 수 있다고 해요. Nate가 말하는 Glido의 비전은 목소리만으로 컴퓨터 전체를 다루고, 책상을 떠나 있어도 앉아 있을 때만큼 일하는 것이에요. 커맨드 모드 없이 받아쓰기만 써도 이메일이나 SOP를 쓸 때 시간이 많이 아껴진다고 해요. 말하는 게 타이핑보다 빠르니까요.

Kie.ai는 이미지·영상판 OpenRouter, trigger.dev는 서버 없는 코드 실행이에요

여섯 번째 Kie.ai는 Nate의 표현으로 이미지와 영상용 OpenRouter예요. Veo, Kling, Seedance, Nano Banana, GPT Image 2 같은 이미지·영상 모델을 한곳에서 쓴 만큼만 내고 써요. 캐러셀, 썸네일, Instagram 릴스용 이미지를 만들 때 늘 Kie.ai를 쓰는데, 생성한 만큼만 돈을 내서 한 번에 많이 만들 때 찾아본 것 중 가장 싸다고 해요. 시청자에게는 제품 사진, 광고 소재, SNS용 짧은 영상에 쓸 수 있다고 하고, 월 구독료 없이 쓴 만큼만 낸다는 점을 강조해요.

마지막 일곱 번째는 trigger.dev예요. TypeScript 코드를 올려 두면 일정에 따라, 또는 웹훅 같은 이벤트가 생길 때 실행해 줘요. VPS와 달리 관리할 서버가 없고 코드만 실행돼요. Nate의 회사는 문서 처리나 두 도구 사이의 데이터 동기화처럼 매번 같은 단계를 밟는 결정론적(deterministic, 결과가 예측 가능한) 자동화에 늘 이걸 써요.

이런 일에 Claude Code 같은 에이전트 루프 전체를 돌리는 건 낭비이고 과하다는 게 Nate의 생각이에요. 그래서 Claude Code로 스크립트를 만들고 그 스크립트를 trigger.dev에 넣어 자동으로 돌려요. trigger.dev를 열어 볼 필요도 없다고 해요. Claude Code에 "이 용도로 TypeScript trigger.dev 자동화를 만들어 줘"라고 하면 만들고 배포하고 테스트하고 업데이트까지 해 준다는 거죠.

코드만 돌리니 비용도 아주 낮아요. 실행되는 순간만큼만 내면 되고, 무료 플랜에 매달 5달러 크레딧이 들어 있어서 꽤 오래 쓸 수 있다고 해요. 내 사업이나 고객사에 코드 기반 결정론적 자동화를 여럿 깔아야 한다면 trigger.dev를 꼭 권한다고 말합니다.

마지막으로 Nate는 이게 자기 목록이라는 점을 분명히 해요. 시간이 지나며 바뀌긴 하지만, 1년 반에서 2년 가까이 꾸준히 돌아오는 7개라고 합니다. 하는 사업이 다르면 이 목록이 딱 맞지 않을 수 있고, 그래도 괜찮다고 해요. 처음엔 배우는 게 부담스러울 수 있어서 채널과 커뮤니티에서 최대한 많이 다루려 한다고 덧붙이며 마무리해요.

핵심 인사이트

  • 에이전트 하나가 여러 구독을 대신해요: Nate는 Claude Code·Codex로 Gamma, Poppy 같은 유료 도구를 직접 만든 앱으로 바꿨어요. 혼자나 작은 팀이 쓰는 수준이면 위험이 크지 않다고 보고, 기능 하나만 쓰는 구독부터 바꿔 보라고 해요.
  • 도구보다 갈아탈 수 있는 구조가 중요해요: Claude Code와 Codex 중 앞서는 쪽은 몇 달마다 바뀌어요. 그래서 Nate는 파일·폴더·프로젝트를 두 도구가 함께 쓸 수 있게 짜 두고, OpenRouter로 모델 교체를 한 줄 수정으로 끝내요.
  • 모든 자동화에 AI가 필요하진 않아요: 매번 같은 단계를 밟는 일은 에이전트 대신 스크립트로 만들어 trigger.dev에 올리는 게 싸고, 에이전트를 쓰는 건 과하다는 게 Nate의 판단이에요. 판단이 필요한 일과 반복만 하는 일을 나누는 데서 비용 차이가 생겨요.

오늘 당장 해볼 것

  1. 지난달 카드 명세서에서 매달 내면서 기능 하나만 쓰는 도구를 하나 찾아보세요. 그 기능만 Claude Code나 Codex에 설명해 작은 앱으로 만들어 보면, 구독을 끊어도 되는지 감이 옵니다.
  2. 돌리고 있는 자동화가 있다면 OpenRouter에서 자동화별로 API 키를 따로 만들고 폴백 모델을 하나 지정해 보세요. 어느 자동화에 돈이 얼마나 드는지 바로 보이고, 모델 하나가 멈춰도 전체가 서지 않아요.
  3. 매번 같은 단계로 끝나는 작업(문서 처리, 두 도구 간 데이터 동기화)을 하나 골라 Claude Code에 "이 용도로 TypeScript trigger.dev 자동화를 만들어 줘"라고 요청해 보세요. 무료 플랜의 월 5달러 크레딧으로 먼저 시험해 볼 수 있어요.
