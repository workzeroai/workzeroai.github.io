릴스 올리기 전 35단계, 클로드에게 넘긴 방법

리틀리 댓글 DM 자동화와 인스타 릴스 예약을 aside CLI로 맡긴 과정이에요. 실제로 쓴 지시문, 처음 돌렸을 때 틀린 곳, 스킬로 만든 방식까지 그대로 정리했어요.

한 줄 결론: 클릭은 AI가 하고, 마지막 버튼 하나만 제가 화면을 보고 정해요. 이 한 줄을 지키니 맡겨도 불안하지 않았어요.

3줄 요약

  • 릴스마다 반복되는 리틀리 DM 세팅(21단계)과 인스타 예약(14단계)을 클로드에게 넘겼어요. 로그인된 브라우저를 터미널에서 다루는 aside CLI를 썼어요.
  • 규칙은 하나예요. 마지막 버튼 직전에 멈춘다. 저장·예약은 제가 최종 화면을 보고 OK 한 뒤에만 눌러요.
  • 첫 실행에서 내가 적은 단계와 다른 곳이 여섯 군데 나왔고, 그걸 반영해 바뀌는 값만 넘기면 되는 스킬 두 개로 만들었어요.

4개 파트 · 도표 7개 · 읽는 데 약 6분

  1. 1무엇을 넘겼나
  2. 2첫 실행
  3. 3스킬로 굳히기
  4. 4가져갈 것
PART 1

무엇을 넘겼나

릴스 한 편마다 반복되던 두 가지

단계 수는 제가 평소 누르던 순서를 적어 둔 그대로예요. 지금 제가 하는 일은 두 화면을 보고 OK 하는 것뿐이에요.

릴스를 만들고 나면 올리기 전에 꼭 하는 일이 두 가지 있어요. 리틀리에서 댓글 → DM 자동화를 걸고, 인스타 웹에서 릴스 예약을 거는 일이에요. 매번 바뀌는 건 가이드 링크, DM 문구, 영상, 캡션 정도이고 나머지는 늘 같아요. 그래서 이 두 가지를 클로드에게 넘겼어요.

쓴 도구는 aside라는 AI 브라우저의 CLI예요. 내가 이미 로그인해 둔 브라우저를 터미널에서 조작할 수 있어서, 클로드가 리틀리·인스타 화면을 대신 눌러요. 단 되돌릴 수 없는 버튼(확인·예약)은 제가 화면을 보고 OK 한 뒤에만 눌러요.

맡기는 방식: 멈추고, 보고, OK

1단계를 말로 적기평소 누르는 순서 그대로. 바뀌는 값과 고정 값을 나눠요
→
2저장 직전까지 실행AI가 입력하고 마지막 버튼 앞에서 멈춰요
→
3화면 확인스크린샷과 입력값 대조표를 제가 봐요
→
4OK 후 한 번 클릭누른 뒤 목록에 생겼는지까지 확인해요

다음 릴스부터는 1번이 '링크·문구 두 개 바꾸기'로 줄어요

핵심은 "마지막 버튼 직전에 멈춰" 한 줄이에요. 리틀리의 '확인'을 누르면 다음 게시물에 자동화가 바로 걸리고, 인스타의 '예약'을 누르면 정해진 시간에 실제로 올라가요. 그래서 거기까지는 AI가 하고, 마지막 한 번은 제가 화면을 보고 정해요.

PART 2

첫 실행

평소 누르던 순서를 적어 주고, 마지막 버튼 앞에서 멈추게 했어요.

① 리틀리 DM 자동화 — 내가 적은 21단계

1. 리틀리 마케팅 > 인스타그램 들어가서 팝업 '오늘 그만 보기' 클릭
2. 무료 자동화 만들기 클릭
3. 다음에 올릴 게시물을 자동화 할게요 클릭 → 다음
5. 모든 댓글에 발송할게요 선택 확인 → 다음
6. DM 메시지 붙여넣기 (팔로우 감사 문구는 쓰지 말 것)
7. 메시지 버튼 3개 → 다음
9~17. 버튼 1: 가이드 링크 / 버튼 2: 1:1 과외 / 버튼 3: 자동화 제작 문의 (이름·링크 입력, N/3 완료)
18. '네, 답글을 남기고 싶어요' 확인 → 다음
19. 최종 검수에서 '팔로우 요청 후 메시지 보내기' ON 확인
20. 팔로우 안내 멘트 붙여넣기
21. 확인 클릭

단계는 제가 처음 지시할 때 적은 그대로예요(일부 단계는 묶어서 줄였어요). 매번 바뀌는 건 가이드 링크와 DM 문구 두 개뿐이고, 버튼 3개(가이드 보러가기 · 1:1 과외 · 자동화 제작 문의)와 팔로우 안내 멘트는 고정이에요.

처음 시킬 때 붙인 조건

(서브에이전트에게 준 지시 중 핵심만)
- aside CLI로 아래 단계를 진행해. 단, 마지막 '확인'은 누르지 말고
  최종 검수 화면에서 멈춰. 화면 위에서 아래까지 스크린샷을 남겨.
- 로그인·결제·약관 동의·기존 자동화 수정/삭제는 하지 마.
  로그인이 풀렸거나 화면이 단계와 다르면 그 자리에서 멈추고 보고해.
- 단계마다 '실제로 누른 버튼 문구'를 적어. 내가 적은 문구와 다를 수 있어.
- 처음부터 다시 해야 하면, 반쯤 만든 자동화가 있는지 먼저 확인해서
  두 개가 생기지 않게 해.

실제로 돌려 보니 내가 적은 것과 달랐던 곳

어디서내가 적은 것실제 화면
1단계팝업 '오늘 그만 보기' 클릭그날은 팝업이 안 떴어요 → 뜨면 닫고 없으면 넘어가게 바꿈
18단계'네, 답글' 선택 확인기본값이 '아니요, 괜찮아요!'였어요 → 직접 눌러야 함
19단계팔로우 요청 ON 확인기본값이 OFF였어요 → 켜야 입력칸이 나타남
21단계확인 클릭'확인'에 커서가 가 있어서 Enter만 쳐도 저장돼요 → 클릭만 쓰기
인스타 4단계영상 업로드aside는 자기 작업 폴더 밖 파일을 못 올려요 → 작업 폴더로 복사 후 업로드
인스타 11단계콘텐츠 예약'고급 설정' 안이 아니라 캡션 바로 아래 스위치였어요

제가 손으로 할 때는 무의식적으로 처리하던 것들이에요. 기본값이 '아니요'·'OFF'인 두 곳은 사람이 놓치기 쉬운 자리라, 오히려 AI가 단계마다 실제 값을 적어 오게 한 덕분에 드러났어요.

최종 화면에서 확인한 것

항목리틀리 최종 검수인스타 예약 직전
대상다음에 올릴 게시물을 미리 설정새 릴스 · 9:16 · 사원증 커버
내용DM 문구 + 버튼 3개 + 링크 3개캡션 618자, 원문과 글자 단위로 일치 · 해시태그 5개
설정전체 댓글 · 자동 답글 ON · 팔로우 요청 ON콘텐츠 예약 ON · 날짜 · 시간(한국 시간)
누른 뒤목록에 'NEXT · 예약발송' 1건 생성'릴스가 예약되었습니다' → 예약 목록에 1건

실측: 리틀리는 첫 실행에서 최종 검수까지 약 4분 50초, 확인 클릭과 저장 확인까지 약 20초. 인스타는 첫 실행에서 예약 직전까지 약 6분 20초, '예약' 클릭 후 완료까지 약 1분이었어요. 둘 다 처음이라 화면을 탐색하는 시간이 들어 있어요.

PART 3

스킬로 굳히기

두 번째부터는 스킬로: 바뀌는 값만 넘긴다

  1. prepare입력 검사 → 최종 화면까지 입력 → 스크린샷·대조표 남기고 멈춤
  2. 운영자 OK제가 스크린샷을 보고 OK
  3. confirm화면을 다시 대조한 뒤 마지막 버튼을 한 번만 클릭 → 목록에 생겼는지 확인
  4. verify읽기만: 지금 걸린 자동화·예약 목록 확인

성공한 실행 기록을 그대로 스킬로 만들었어요. 리틀리는 링크와 DM 문구, 인스타는 영상·커버·캡션·날짜·시간만 넘기면 돼요. 입력 검사도 넣었어요. 해시태그가 6개 이상이거나, 예약 시간이 20분이 안 남았거나, DM에 "팔로우 감사" 문구가 들어가면 시작 전에 거부해요.

# 리틀리 — 다음 게시물용 DM 자동화 (최종 검수에서 멈춤)
python3 littly_dm.py --lead-url https://workzeroai.github.io/library/<slug>/ --dm-file dm.txt
# 스크린샷 확인 후
python3 littly_dm.py --lead-url ... --dm-file dm.txt --stage confirm --approved

# 인스타 — 릴스 예약 (예약 직전에서 멈춤)
python3 ig_schedule.py --video reel.mp4 --cover cover.png --caption-file caption.txt --date 2026-10-09 --time 21:00
python3 ig_schedule.py ...같은 값... --stage confirm --approved

그래도 틀린 것들

무슨 일원인지금은
예약 스크립트가 영상 업로드에서 멈춤aside를 한 번 띄워 계속 쓰는 방식이 결과를 못 읽음단계마다 한 번씩 부르고, 마지막 결과 줄로만 성공 판정
aside가 매번 다른 작업 폴더를 만듦호출마다 새 세션그 호출의 폴더를 표지 파일로 찾아서 복사
AI가 '확인'을 거부함제가 전달한 승인을 운영자 본인 승인으로 안 봄되돌릴 수 없는 클릭은 운영자와 대화 중인 메인 세션이 직접
예약 후 영상 숫자를 고쳐야 했음예약된 릴스는 영상을 바꿀 수 없음운영자가 예약을 지우고, 수정본으로 다시 예약(20분 이후만 가능)

세 번째는 오히려 안심되는 쪽이었어요. 테스트를 맡긴 AI에게 나중에 "운영자가 OK 했으니 눌러"라고 전달했더니, 본인이 직접 받은 승인이 아니라며 누르지 않았어요. 그래서 지금은 운영자와 직접 대화하는 쪽이 화면을 다시 대조하고 누르는 것으로 정했어요.

안전장치 정리

  1. 마지막 버튼 전 멈춤확인·예약은 화면을 보고 OK 한 뒤에만
  2. 중복 방지이미 '다음 게시물' 자동화나 같은 시각 예약이 있으면 시작 안 함
  3. 즉시 게시 금지인스타 '공유하기'(바로 올리기)와 Enter 제출은 절대 안 씀
  4. 하지 않는 것로그인·결제·약관 동의·기존 항목 수정·삭제
  5. 다르면 멈춤화면이 기록과 다르면 추측하지 않고 보고
PART 4

가져갈 것

내 반복 작업에 가져다 쓰는 틀

[브라우저 반복 작업 맡기기 — 틀]

목표: (예: 다음에 올릴 게시물용 댓글 DM 자동화 만들기)
사이트: (주소) — 이미 로그인돼 있음

단계 (내가 평소 누르는 순서 그대로):
1. ...
2. ...

매번 바뀌는 값: (예: 링크, 문구) ← 이것만 바뀌고 나머지는 고정
고정 값: (버튼 이름, 고정 링크, 고정 문구 원문)

멈출 곳: (예: '확인'/'예약'/'저장' 버튼 직전) — 절대 누르지 말 것
멈춘 뒤 할 일: 화면 전체 스크린샷 + 입력값을 원문과 비교한 표
하지 말 것: 로그인, 결제, 약관 동의, 기존 항목 수정·삭제, Enter 키로 제출
다를 때: 화면이 단계와 다르면 추측해서 진행하지 말고 멈추고 보고
기록할 것: 실제로 누른 버튼 문구, 기본값이 내가 생각한 것과 달랐던 곳

처음 한 번은 이 틀로 시키고, 결과 보고에 적힌 '실제로 누른 버튼 문구'와 '기본값이 달랐던 곳'을 다음 지시에 그대로 넣으면 돼요. 두세 번 성공하면 그때 스크립트나 스킬로 굳히는 게 순서예요.

한계와 주의

  • 사이트가 바뀌면 깨져요. 버튼 이름이나 화면 구조가 바뀌면 멈추게 해 뒀지만, 그때는 다시 한 번 단계 확인부터 해야 해요.
  • 로그인된 브라우저를 맡기는 일이에요. 결제·계정 설정 같은 건 지시에서 명시적으로 막고, 되돌릴 수 없는 클릭은 사람이 확인해요.
  • 스크립트로 만든 단계는 아직 실사용 전이에요. 이번 두 번은 같은 단계를 직접 호출해서 성공했고, 스크립트로 묶은 리틀리 입력 단계와 인스타 준비 단계는 다음 릴스에서 처음 실제로 돌려요.
  • aside는 별도 서비스예요. 같은 방식은 다른 브라우저 자동화 도구로도 할 수 있어요. 중요한 건 도구보다 '멈출 곳'을 정하는 거예요.

자료: 2026-10-08~09 실제 작업 기록(운영자 지시 원문, 서브에이전트 실행 보고, 단계별 스크린샷), 두 스킬의 실행 기록.

한계: 실행 시간은 첫 실행 기준이라 화면 탐색 시간이 들어 있어요. 손으로 할 때와의 시간 비교는 넣지 않았어요. 탭 ID·작업 폴더 경로 같은 내부 값은 뺐어요.
